# AI 与 FDE 术语表

## 使用约定

本页给出 AI 应用工程与 FDE 中高频术语的最小定义，用于统一表达，不替代权威概念笔记。各领域笔记尚未创建，因此暂不为术语添加内部占位链接；未来已有权威笔记时再把术语名替换为真实相对链接。

同一术语在论文、产品和团队中可能有不同边界。进行设计或评审时，应进一步写明输入输出、控制权、失败模式和度量方式。

## 模型与表示

- **Token（词元）：** Tokenizer 处理文本时使用的离散单位，可能是字符、子词、字节或特殊标记；它不是天然等同于一个汉字或英文单词。
- **Tokenizer（词元化器）：** 在文本与 Token ID 序列之间转换的组件，其词表和规则必须与模型训练配置匹配。
- **Vocabulary（词表）：** Token 与整数 ID 的映射集合；大小会影响表示粒度、Embedding 参数量和序列长度。
- **Embedding（嵌入）：** 把离散对象映射为稠密向量的表示；相似度只有在对应模型、任务和度量下才有意义。
- **Transformer：** 以 Attention 为核心、支持并行序列建模的神经网络架构，是现代 LLM 和多种视觉语言模型的基础。
- **Attention（注意力）：** 根据 Query 与 Key 的相关性对 Value 加权聚合的机制，用于在上下文中选择信息。
- **LLM（大语言模型）：** 在大规模文本或多模态数据上训练、以语言理解和生成为主要接口的模型。
- **VLM（视觉语言模型）：** 联合处理图像与语言信息的模型，可用于视觉问答、文档理解和多模态推理。
- **Context Window（上下文窗口）：** 一次模型请求可处理的 Token 范围，通常包含系统指令、用户输入、工具信息、检索内容和输出预算。
- **KV Cache：** 自回归推理时缓存 Attention 的 Key/Value 状态，以减少重复计算，但会消耗显存或内存。
- **Inference（推理）：** 使用已训练模型对新输入生成预测或输出的运行阶段。
- **Sampling（采样）：** 按模型输出概率选择下一个 Token 的过程，常受 temperature、top-p 等参数影响。
- **Hallucination（幻觉）：** 模型生成缺少输入或可靠证据支持、却呈现为事实的内容；不能仅靠语气判断。
- **Grounding（证据约束）：** 让输出基于可检查的数据、上下文或工具结果，并保留从结论到证据的关系。

## 模型适配与服务

- **Fine-tuning（微调）：** 在预训练模型上继续训练，以改变任务行为、领域适配或输出风格；不天然解决知识时效与引用问题。
- **SFT（监督微调）：** 使用输入与目标输出样本进行监督训练的微调方式。
- **PEFT（参数高效微调）：** 只训练少量新增或选定参数的适配方法集合，以降低训练和存储成本。
- **LoRA（低秩适配）：** 通过可训练低秩矩阵近似权重更新的一种 PEFT 方法。
- **RLHF（基于人类反馈的强化学习）：** 使用人类偏好相关信号对模型行为进行强化学习优化的一类方法。
- **DPO（直接偏好优化）：** 直接使用偏好对优化模型、避免显式训练传统奖励模型与在线强化学习循环的方法。
- **Distillation（蒸馏）：** 让较小或更高效的学生模型学习教师模型行为或表示的方法。
- **Quantization（量化）：** 用更低精度表示权重或激活，以降低存储、显存与推理成本，可能带来质量或算子兼容损失。
- **vLLM：** 面向 LLM 推理与服务的开源引擎，重点能力包括高吞吐调度和高效 KV Cache 管理。
- **Structured Output（结构化输出）：** 约束模型结果满足预定义 JSON Schema 或其他机器可验证结构的能力。
- **Function Calling（函数调用）：** 模型根据可用工具描述产生结构化调用意图，由应用执行函数并把结果返回模型；模型本身不直接执行函数。
- **Model Gateway（模型网关）：** 在应用与模型供应商之间统一认证、路由、限流、审计、Fallback 和成本策略的服务层。
- **Fallback（降级切换）：** 首选模型或组件失败、超时或不满足策略时，切换到备用路径的机制。

## 检索增强生成

- **RAG（检索增强生成）：** 在生成前检索外部信息并把相关证据加入上下文的系统模式，目标通常是提高可核验性、时效性或领域覆盖。
- **Sparse Retrieval（稀疏检索）：** 基于词项稀疏表示进行匹配的检索方法，对精确关键词、编号和罕见实体通常较敏感。
- **Dense Retrieval（稠密检索）：** 使用向量表示和相似度搜索语义相关内容的检索方法。
- **Hybrid Search（混合检索）：** 组合稀疏与稠密检索结果，以利用词法匹配和语义匹配的互补性。
- **BM25：** 基于词频、逆文档频率和文档长度归一化的经典概率相关性排序函数。
- **Vector Database（向量数据库）：** 存储向量及元数据、支持近似或精确相似度检索的系统；它只是 RAG 的可选组件之一。
- **Chunking（切分）：** 把源内容划分为可索引与可注入上下文的单元，需要权衡语义完整性、召回、噪声和成本。
- **Metadata Filtering（元数据过滤）：** 在检索前或检索中按租户、权限、时间、类型等结构化字段限制候选集合。
- **Reranker（重排序器）：** 对初始候选进行更精细的相关性评分并重新排序的模型或规则。
- **RRF（倒数排名融合）：** Reciprocal Rank Fusion，一种按各列表名次倒数合并多个排序结果、无需直接比较原始分数的方法。
- **Query Rewrite（查询改写）：** 把用户输入改写为更适合检索的查询，同时需要防止意图漂移和权限绕过。
- **HyDE：** Hypothetical Document Embeddings，先生成假设性相关文档，再使用其向量进行检索的方法。
- **GraphRAG：** 利用图结构、实体关系或层次摘要增强检索与生成的一类方法；具体实现边界依项目而异。
- **Agentic RAG：** 由 Agent 根据状态动态决定是否检索、检索什么、如何迭代或调用其他工具的 RAG 形态。
- **Citation（引用）：** 输出中指向支持性来源的可检查关系；有链接不代表来源真的蕴含该结论，仍需评测引用正确性。

## Agent 与互操作

- **Agent（智能体）：** 在目标和约束下，由模型结合状态与工具循环选择行动的系统；自主程度应与风险相匹配。
- **Workflow（工作流）：** 由代码或配置预先规定主要步骤和分支的执行流程，通常比开放式 Agent 更可预测。
- **ReAct：** 交替进行推理与行动、再根据观察结果继续决策的 Agent 模式。
- **Tool（工具）：** 暴露给模型或工作流的受控能力，必须定义输入 Schema、权限、超时、副作用和错误语义。
- **State（状态）：** 工作流推进所需的结构化事实，例如当前步骤、工具结果、审批状态和错误信息。
- **Memory（记忆）：** 跨消息、会话或任务保存并检索信息的机制，不等同于模型上下文窗口。
- **Session（会话）：** 将一次连续交互的身份、状态和生命周期关联起来的边界。
- **HITL（人在回路）：** Human-in-the-Loop，在高风险、低置信度或策略规定的节点由人审查、批准或接管。
- **Idempotency（幂等）：** 同一操作被重复执行时不会产生额外不期望副作用的性质，是重试和恢复的重要前提。
- **MCP（模型上下文协议）：** Model Context Protocol，用于让 AI 应用以标准方式连接工具、资源和提示的开放协议。
- **A2A（Agent2Agent 协议）：** 用于不同 Agent 之间发现能力、交换任务与结果的开放互操作协议。
- **Supervisor（监督者）：** 在多 Agent 系统中负责任务分派、结果汇总或策略控制的协调组件，不保证天然优于单 Agent。

## 评测、可观测性与安全

- **Evaluation / Eval（评测）：** 使用明确数据、指标和判定流程衡量系统行为；应区分组件、端到端、离线和在线评测。
- **Golden Dataset（黄金数据集）：** 经过审查、包含预期输入输出或判定依据的高质量评测样本集合，需要持续版本化。
- **LLM-as-Judge：** 使用语言模型评判其他模型或系统输出的方法，需校准偏差、位置效应、一致性和与人工判断的相关性。
- **Tracing（链路追踪）：** 记录一次请求跨模型、检索、工具与服务的执行步骤、时间、输入输出摘要和错误，用于调试与评测。
- **Observability（可观测性）：** 通过 Trace、日志、指标和反馈推断系统内部状态并回答未知问题的能力。
- **Guardrail（护栏）：** 在输入、执行或输出阶段实施的策略与技术控制，例如校验、权限、内容过滤、预算和人工审批。
- **Prompt Injection（提示注入）：** 攻击者通过直接或间接输入操纵模型偏离系统意图、泄露数据或调用不当工具的攻击方式。
- **Indirect Prompt Injection（间接提示注入）：** 恶意指令藏在网页、文档、邮件等被系统读取的外部内容中，而非由用户直接输入。
- **Data Exfiltration（数据外泄）：** 敏感数据越过授权边界被读取、传输或暴露，可能经模型输出、工具、日志或第三方服务发生。
- **Least Privilege（最小权限）：** 仅授予完成当前任务所需的最小数据与操作权限，并限制范围和持续时间。
- **PII（个人可识别信息）：** Personally Identifiable Information，可单独或组合识别个人的信息，其定义和处理义务依司法辖区与场景而异。
- **Red Teaming（红队测试）：** 以对抗视角系统寻找滥用、安全和失效路径，并将发现转化为测试和控制。
- **SLO（服务等级目标）：** Service Level Objective，对可用性、延迟或正确性等服务指标设定的内部目标。

## FDE 与交付

- **FDE（前沿部署工程师）：** Forward Deployed Engineer，深入客户环境、连接技术与业务并对端到端交付结果负责的工程角色。
- **Discovery（需求发现）：** 通过访谈、数据和流程观察验证用户、问题、约束、价值与风险，而非只收集功能愿望。
- **PoC（概念验证）：** Proof of Concept，用有限范围验证关键可行性或风险假设；它不是生产上线的同义词。
- **Acceptance Criteria（验收标准）：** 在实施前约定、可观察且可判断的完成条件，包括质量、业务、安全与运行要求。
- **ROI（投资回报率）：** 收益相对投入的衡量方式；AI 项目还应计入数据、评测、人工审核、运行和变更管理成本。
- **Runbook（运行手册）：** 面向日常操作和故障场景的可执行说明，包含前提、步骤、验证、升级与恢复方式。
- **Handover（交接）：** 将系统知识、权限、运行责任和未决风险转移给长期所有者的过程，不是一次文档发送。
- **Productization（产品化）：** 把多个真实交付中的稳定共性转化为有接口、测试、版本与维护责任的产品能力。
