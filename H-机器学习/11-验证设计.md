# 验证设计

<!-- markdownlint-disable MD012 MD013 -->

## 它解决什么机器学习问题

验证设计回答：用历史数据测出的效果，能否代表模型面对真实未来样本的效果。拆分方式应模拟部署，而不是机械选择随机 8:2。

## 不理解会造成什么错误

- 同一用户或患者同时出现在训练和测试中。
- 时间序列随机打乱，让模型用未来预测过去。
- 用测试集选参数，测试集退化为验证集。
- 只报一次拆分的最好结果，不说明波动。

## 它在建模工作流中的位置

在看模型之前先确定部署单位和数据边界。所有预处理、特征选择、重采样与调参都必须在训练折内完成。测试集最后只回答一次“冻结方案表现如何”。

## 从部署方式选择拆分

| 部署问题 | 合适设计 |
| --- | --- |
| 未来随机到来的独立样本 | 分层 Holdout 或 K 折 |
| 为从未见过的新客户预测 | GroupKFold，客户不跨折 |
| 用过去预测未来 | 时间留出或 TimeSeriesSplit |
| 调参后仍需无偏估计 | 嵌套交叉验证 |

分类分层只能保持各折类别比例，不能解决时间或实体重叠。

## 核心机制

K 折把数据分为 $K$ 份，轮流用一份验证、其余训练：

$$
\bar s=\frac{1}{K}\sum_{k=1}^{K}s_k
$$

均值估计典型表现，各折标准差反映拆分敏感性。嵌套验证的外层估计泛化，内层只负责选参数，避免把选择过程泄漏到最终估计。

## 最小手算

五折分数为 0.72、0.76、0.74、0.90、0.73，均值约 0.77。只报 0.90 会误导；异常高的一折还提示实体重叠、样本容易或分布差异，应检查折组成。

## 可执行实验

```python
import numpy as np
from sklearn.model_selection import GroupKFold, KFold, TimeSeriesSplit

groups = np.repeat(np.arange(6), 2)
X = np.arange(12).reshape(-1, 1)
y = groups % 2
for name, splitter, kwargs in (
    ("random", KFold(n_splits=3, shuffle=True, random_state=42), {}),
    ("group", GroupKFold(n_splits=3), {"groups": groups}),
):
    train, test = next(splitter.split(X, y, **kwargs))
    overlap = set(groups[train]) & set(groups[test])
    print(name, "group overlap", sorted(overlap))

for train, test in TimeSeriesSplit(n_splits=3).split(X):
    print("time", train[[0, -1]].tolist(), test[[0, -1]].tolist())
```

随机 K 折可能让相同实体跨集合；GroupKFold 阻止这种重叠；TimeSeriesSplit 保证训练索引早于测试索引。

## 评测与结果解释

先固定主指标和拆分，再比较模型。报告各折分数而不只报均值。若折间差异大，查看时间、地区、实体和标签比例；这可能比换模型更有价值。最终测试集应模拟一次真实上线窗口。

## 数据与泄漏风险

Pipeline 必须位于交叉验证内部。重复样本、同一家庭、设备或门店可能需要分组。时间任务还要考虑标签成熟期：训练窗口与验证窗口之间可增加 gap，防止相邻窗口的信息重叠。

## 工程排错

| 现象 | 可能原因 | 优先检查 |
| --- | --- | --- |
| 不同种子差异很大 | 样本少或分层不足 | 每折分布、置信区间、更多数据 |
| CV 好而新客户差 | 实体跨折 | 用户交集、GroupKFold |
| 随机拆分好时间拆分差 | 漂移或时间泄漏 | 特征时间、分窗口指标 |
| 调参后测试反复下降 | 过度试探测试集 | 实验日志、独立最终集、嵌套 CV |

## 适用与不适用场景

普通 K 折要求样本近似独立同分布。存在组、时间、空间或网络依赖时应定制拆分。交叉验证也不能替代线上实验，因为用户行为可能被模型行动反过来改变。

## 学习收益

你应能根据真实部署选择 Holdout、分层、分组、时间或嵌套验证，解释折间波动，并确保整个预处理与调参过程不看最终测试集。

## 给别人讲清楚

“验证不是把数据随便切开，而是提前排练上线：未来会遇到谁，就让测试集以同样方式成为陌生数据。”
