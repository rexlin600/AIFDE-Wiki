# 特征工程

<!-- markdownlint-disable MD012 MD013 -->

## 它解决什么机器学习问题

模型只能看到数值化输入。特征工程把原始时间、类别、计数和缺失字段变成在预测时可获得、含义稳定、训练与线上一致的信号。

## 不理解会造成什么错误

- 用 `fit_transform` 分别处理训练集和测试集，坐标系不一致。
- 把未知类别编码成已有类别，或让缺失值在服务端变成零。
- 手工复制训练逻辑到线上，版本稍有差异就静默劣化。
- 在拆分前计算均值、目标编码或特征选择，泄漏验证信息。

## 它在建模工作流中的位置

特征工程位于原始数据与模型之间。先确定预测时点和拆分，再只在训练数据上拟合转换器；把转换器与模型封装进 Pipeline 后一起验证和部署。

## 从流失案例开始

每行是一名观察日客户，输入包含近 7 天登录次数、套餐、账龄和缺失的满意度；标签是未来 30 天是否流失。基线只用登录次数，随后再证明新增特征是否稳定改善验证集。

## 核心机制

- **缺失值：** 数值可用训练集中位数，类别可增加“未知”；缺失本身有时也是信号。
- **缩放：** $z=(x-\mu)/\sigma$，让不同量纲对距离或正则化模型更公平。
- **独热编码：** 每个类别变成一个 0/1 列，不虚构大小顺序。
- **时间特征：** 只从预测时点之前构造；周期变量可用正弦和余弦表达首尾相邻。
- **交互：** 表达“两个条件同时成立”，但会增加维度和过拟合风险。

## 最小手算

训练值 `[10, 20, 30]` 的均值是 20，标准差约 8.16。标准化后 30 约为 $(30-20)/8.16=1.225$。测试值不得参与均值和标准差计算，否则验证集信息已经影响输入表示。

## 可执行实验

```python
import numpy as np
from sklearn.impute import SimpleImputer
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import roc_auc_score
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

rng = np.random.default_rng(42)
X = rng.normal(size=(500, 3))
X[rng.random(X.shape) < 0.08] = np.nan
y = ((np.nan_to_num(X[:, 0]) - 0.7 * np.nan_to_num(X[:, 1])) > 0).astype(int)
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.3, stratify=y, random_state=42
)
pipeline = make_pipeline(
    SimpleImputer(strategy="median", add_indicator=True),
    StandardScaler(),
    LogisticRegression(max_iter=1000),
)
pipeline.fit(X_train, y_train)
probability = pipeline.predict_proba(X_test)[:, 1]
print("test AUC", round(roc_auc_score(y_test, probability), 3))
print("train medians", np.round(pipeline[0].statistics_, 3))
```

Pipeline 保证交叉验证每一折只用该折训练部分学习填补值和缩放参数，也能作为一个整体保存和服务。

## 评测与结果解释

用消融实验逐组加入特征，比较多折均值、方差、延迟和缺失切片表现。验证提升小于折间波动时，不要宣称新特征有效。特征数量增加还要考虑生成成本和线上可用率。

## 数据与泄漏风险

任何聚合都要回答“统计截止到几点”。目标编码必须在训练折内部、最好使用折外统计。测试集只能调用 `transform`。训练与线上共享同一特征定义、时区、窗口闭合规则和缺失约定。

## 工程排错

| 现象 | 可能原因 | 优先检查 |
| --- | --- | --- |
| 线上输入列错位 | 手工拼列或版本不一致 | Pipeline、列名、模型签名 |
| 未知类别报错 | 编码器未容忍新类别 | `handle_unknown`、类别分布 |
| 离线好线上差 | 时间穿越或计算口径不同 | 特征时间戳、离在线样本对账 |
| 加特征反而变差 | 噪声、共线或样本减少 | 消融、缺失率、正则化 |

## 适用与不适用场景

所有生产模型都需要可复现的特征流程。树模型通常不需要缩放，但仍需要稳定的缺失值、类别和时间定义。不要为了“特征更多”引入预测时不可得或维护成本过高的字段。

## 学习收益

你应能区分 `fit` 与 `transform`，建立无泄漏 Pipeline，解释常见编码和缩放，并通过消融证明特征价值。

## 给别人讲清楚

“特征工程不是美化数据，而是规定模型在预测那一刻究竟能看到什么，并确保训练和线上使用同一把尺子。”
