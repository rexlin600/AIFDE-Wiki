# 聚类

<!-- markdownlint-disable MD012 MD013 -->

## 它解决什么机器学习问题

聚类在没有标签时，把相似样本组织成组。例如根据频率、客单价和品类偏好形成用户群，用于理解人群和提出运营假设。簇不是天然存在的“真相”，而是由特征、距离和算法共同定义的视角。

## 不理解会造成什么错误

- 未缩放金额与次数，让大数值字段支配距离。
- 看到二维图分开就给人群贴上确定标签。
- 用轮廓系数选完簇数，就宣称运营策略有效。
- 每次重训簇编号变化，线上规则仍沿用旧编号。

## 它在建模工作流中的位置

先明确聚类输出要支持什么动作，再确定观察窗口和特征。聚类后要做稳定性、可解释性与业务实验，而不是像监督学习那样只看标签准确率。

## 从用户分群开始

样本是过去 90 天有行为的用户，特征是购买次数、平均金额、折扣占比和品类分布，输出是簇及到簇中心的距离。预测时点是观察窗口结束；未来消费不能用于本次分群。简单基线是按单个关键指标做业务分桶。

## 核心机制

K-Means 交替执行两步：把每个样本分给最近中心，再把中心更新为簇内均值。它最小化簇内平方距离：

$$
J=\sum_{i=1}^{n}\lVert x_i-\mu_{c_i}\rVert_2^2
$$

因此它偏好近似球形、大小相近的簇，并对尺度和离群点敏感。层次聚类提供树状合并关系；DBSCAN 等密度方法能发现不规则形状和噪声，但参数含义同样依赖尺度。

## 最小手算

一维用户消费 `[1,2,9,10]`，初始中心为 1 和 10。分配后两簇为 `[1,2]` 与 `[9,10]`，新中心为 1.5 和 9.5；再次分配不变，算法收敛。

## 可执行实验

```python
import numpy as np
from sklearn.cluster import KMeans
from sklearn.datasets import make_blobs
from sklearn.metrics import silhouette_score
from sklearn.preprocessing import StandardScaler

X, _ = make_blobs(n_samples=400, centers=3, cluster_std=1.2, random_state=42)
X[:, 1] *= 100
for name, data in (("raw", X), ("scaled", StandardScaler().fit_transform(X))):
    for k in (2, 3, 4):
        labels = KMeans(n_clusters=k, n_init=20, random_state=42).fit_predict(data)
        print(name, k, round(silhouette_score(data, labels), 3))
```

缩放改变了“相似”的含义，也会改变最优簇数。轮廓系数越大表示簇内更紧、簇间更远，但不保证群组可行动。

## 评测与结果解释

同时检查内部指标、不同随机种子的簇稳定性、时间窗口稳定性、簇规模和业务画像。最终用下游策略实验回答：分群是否比简单业务规则带来增量价值。

## 数据与泄漏风险

统一特征统计窗口，避免把不同生命周期用户直接比较。缩放器只在基准人群拟合。若分群用于未来活动，画像和命名只能使用预测时点前数据，效果验证使用之后的数据。

## 工程排错

| 现象 | 可能原因 | 优先检查 |
| --- | --- | --- |
| 一个字段决定所有簇 | 尺度差异 | 分布、单位、StandardScaler |
| 小改数据簇就重排 | 初始化或结构不稳定 | 多种子一致性、匹配簇中心 |
| 有一个巨大簇 | K-Means 假设不合适 | 离群点、密度方法、特征 |
| 画像清晰但活动无效 | 描述不等于可行动 | 对照实验、简单分桶基线 |

## 适用与不适用场景

聚类适合探索、压缩人群和形成假设。不适合把簇直接当成真实身份或因果人群；若已有明确业务标签，应先考虑监督学习。

## 学习收益

你应能解释 K-Means 的目标，判断缩放影响，比较簇数，并用稳定性和业务实验而非漂亮图形验证结果。

## 给别人讲清楚

“聚类不是发现宇宙中唯一正确的人群，而是按我们选定的特征和距离，把相似用户放在一起，帮助提出可检验的策略。”
