# 异常检测

<!-- markdownlint-disable MD012 MD013 -->

## 它解决什么机器学习问题

异常检测寻找与常态明显不同的交易、设备状态或访问行为。异常只表示“罕见或不一致”，不自动等于欺诈、故障或错误，最终仍需调查或标签确认。

## 不理解会造成什么错误

- 把模型输出的异常率当成真实欺诈率。
- 用包含已知攻击的全量数据定义“正常”。
- 只看检测数量，不评估调查成本与漏报。
- 全局阈值忽略不同用户、设备或时段的正常差异。

## 它在建模工作流中的位置

当高质量标签不足时，先建立规则或无监督异常分数，再用人工复核、延迟标签和线上调查结果闭环。标签成熟后，应与监督[分类](02-分类.md)比较。

## 从罕见交易开始

样本是一笔支付交易，特征是金额、时间、设备变化和短期交易频率，输出是异常分数。预测发生在授权前，退款和拒付结果此时不可用。误报会打扰正常客户，漏报会造成资金损失。

## 核心机制

简单统计基线可用标准分数 $z=(x-\mu)/\sigma$，但它假设均值和标准差有意义。Isolation Forest 随机选择特征与切分点；异常点通常更容易被少数切分隔离，因此平均路径更短。

`contamination` 主要帮助设定决策阈值，不是算法自动发现的真实异常比例。分数排序与最终报警阈值应分开评估。

## 最小手算

正常金额 `[9,10,10,11]` 的均值为 10，标准差约 0.71。金额 30 的 z-score 约为 28，显然罕见；但若这是高价值客户的正常月付，仅凭全局规则仍会误报。

## 可执行实验

```python
import numpy as np
from sklearn.ensemble import IsolationForest
from sklearn.metrics import average_precision_score

rng = np.random.default_rng(42)
normal = rng.normal(0, 1, size=(500, 2))
anomaly = rng.normal(5, 0.5, size=(20, 2))
X = np.vstack([normal, anomaly])
y = np.r_[np.zeros(len(normal)), np.ones(len(anomaly))]
model = IsolationForest(contamination=0.04, random_state=42)
model.fit(normal[:350])
score = -model.decision_function(X)
print("average precision", round(average_precision_score(y, score), 3))
top = np.argsort(score)[-20:]
print("anomalies in top 20", int(y[top].sum()))
```

实验用已知合成标签评价排序。真实场景没有即时标签时，可抽检高、中、低分样本，避免只确认模型挑出的案例。

## 评测与结果解释

有标签时看 PR-AUC、Recall@调查容量和金额加权损失；无标签时看合成异常、历史已知案例、稳定性和分层人工抽检。阈值必须对应每天可调查数量和误报成本。

## 数据与泄漏风险

训练“正常集”若被异常污染，边界会被拉宽；但过度清洗也会排除罕见正常行为。聚合特征必须只使用交易发生前的数据。按时间验证新型异常，不能随机打乱同一事件链。

## 工程排错

| 现象 | 可能原因 | 优先检查 |
| --- | --- | --- |
| 报警量突然翻倍 | 输入漂移或阈值改变 | 特征分布、模型版本、污染率 |
| 全是高金额客户 | 全局尺度忽略个体基线 | 用户内标准化、金额分层 |
| 已知异常排不靠前 | 特征没有刻画行为 | 时间窗口、设备与频率特征 |
| 抽检准确但仍漏损失 | 只抽高分造成确认偏差 | 随机抽检、金额加权 Recall |

## 适用与不适用场景

适合标签稀缺、异常模式变化快、需要候选排序的场景。不适合把“异常”直接当处罚依据；高风险决策需要规则、监督模型、人工或多重证据。

## 学习收益

你应能区分异常分数与异常标签，解释 Isolation Forest 直觉，按调查容量设阈值，并设计无标签条件下的抽检方案。

## 给别人讲清楚

“异常检测是把最不像常态的样本排到前面，它提出值得调查的线索，不负责证明有罪。”
