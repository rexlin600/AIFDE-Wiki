# 在线学习

<!-- markdownlint-disable MD012 MD013 -->

## 它解决什么机器学习问题

在线学习让模型按数据到达顺序增量更新，适合数据放不进内存、模式变化快或需要频繁适应的场景。它不是“自动调用 `partial_fit`”，而是一套顺序评测、漂移监控、版本与回滚机制。

## 不理解会造成什么错误

- 先训练再在同一批数据评测，把学习后的记忆当预测能力。
- 标签延迟时把尚未成熟样本当负类。
- 无限制追随近期数据，灾难性遗忘稳定规律。
- 自动更新后没有版本、审计和回滚能力。

## 它在建模工作流中的位置

离线模型和验证仍是起点。只有证明数据变化速度或规模需要增量更新，才引入流式特征、先预测后学习的评测、漂移检测和降级方案。

## 从实时流失风险开始

每小时为活跃客户更新流失风险。特征是当时行为，标签要 30 天后才成熟。静态基线每月重训；在线方案在成熟标签到达时更新。错误成本与普通[分类](02-分类.md)相同，但反馈时间线更复杂。

## 核心机制

随机梯度下降每次用小批数据更新参数：

$$
w_{t+1}=w_t-\eta_t\nabla_wL(w_t;x_t,y_t)
$$

学习率太大容易震荡，太小则跟不上漂移。滑动窗口或衰减权重强调近期数据。概念漂移是 $P(y\mid x)$ 改变；仅 $P(x)$ 改变叫协变量漂移，两者应分别监控。

## 最小手算

一维线性模型当前 $w=0.5$，样本 $x=2,y=3$，平方损失梯度为 $2(wx-y)x=2(1-3)2=-8$。学习率 0.1 时，$w'=0.5-0.1(-8)=1.3$。一次样本就可大幅改变权重，说明学习率和异常输入必须受控。

## 可执行实验

```python
import numpy as np
from sklearn.linear_model import SGDClassifier
from sklearn.metrics import accuracy_score

rng = np.random.default_rng(42)
X = rng.normal(size=(1000, 2))
y = np.empty(1000, dtype=int)
y[:500] = (X[:500, 0] + X[:500, 1] > 0).astype(int)
y[500:] = (X[500:, 0] - X[500:, 1] > 0).astype(int)

static = SGDClassifier(loss="log_loss", random_state=42).fit(X[:200], y[:200])
online = SGDClassifier(loss="log_loss", random_state=42)
online.partial_fit(X[:200], y[:200], classes=np.array([0, 1]))
for start in range(200, 1000, 100):
    stop = start + 100
    static_score = accuracy_score(y[start:stop], static.predict(X[start:stop]))
    online_score = accuracy_score(y[start:stop], online.predict(X[start:stop]))
    print(start, round(static_score, 2), round(online_score, 2))
    online.partial_fit(X[start:stop], y[start:stop])
```

代码严格先评测当前批次，再用该批标签更新。500 之后规律改变，静态模型持续失效，在线模型通常经过若干批次适应。

## 评测与结果解释

使用 prequential 评测：先预测，标签成熟后记分，再更新。按事件时间绘制滚动指标，同时保留静态冠军模型、近期窗口基线和线上业务指标。适应快不等于总体好，还要看漂移前性能、波动和恢复时间。

## 数据与泄漏风险

事件时间与处理时间必须区分，迟到事件不能悄悄改写已评测历史。特征转换器也要支持增量更新或使用固定版本。标签成熟前样本保持未知，不得记为负类。

## 工程排错

| 现象 | 可能原因 | 优先检查 |
| --- | --- | --- |
| 更新后指标剧烈震荡 | 学习率过大或批次太小 | 学习率、梯度范数、批量大小 |
| 新规律适应很慢 | 学习率小或旧数据权重大 | 恢复时间、窗口、衰减 |
| 离线回放好线上差 | 事件顺序或标签延迟模拟错误 | event time、成熟规则、迟到数据 |
| 模型突然不可用 | 坏批次或管道版本变化 | 数据契约、版本、回滚与静态兜底 |

## 适用与不适用场景

适合流量大、数据持续到达或变化快且反馈足够及时的任务。若标签几个月后才成熟、监管要求严格或静态模型已稳定满足需求，周期批量重训通常更简单安全。

## 学习收益

你应能解释增量梯度更新，设计先预测后学习的回放，区分两类漂移，并建立版本、回滚和延迟标签机制。

## 给别人讲清楚

“在线学习像边考试边复盘：每道题必须先作答，答案公布后才能更新；还要防止一道异常题把之前学会的规律全部带偏。”
