# 分类

<!-- markdownlint-disable MD012 MD013 -->

## 它解决什么机器学习问题

分类判断样本属于哪个离散类别，例如客户是否会流失。实际系统通常先输出概率，再按成本选择阈值和动作，而不是机械使用 0.5。

## 不理解会造成什么错误

- 正样本仅占 1% 时用准确率，全部预测为负也有 99%。
- 把模型分数当成真实概率，导致预算估计错误。
- 在测试集反复调阈值，使最终报告不再独立。
- 标签定义晚于行动窗口，预测出来也来不及干预。

## 它在建模工作流中的位置

分类连接特征与类别风险。它必须与[指标](06-指标.md)、[校准](10-校准.md)、[验证设计](11-验证设计.md)一起使用，才能从“会不会分”走到“如何行动”。

## 从客户流失案例开始

| 要素 | 定义 |
| --- | --- |
| 样本 | 每月观察日仍在订阅的一名客户 |
| 特征 | 截止观察日的使用频率、工单数、套餐和账龄 |
| 标签 | 未来 30 天是否取消订阅 |
| 预测时点 | 每月观察日当天 |
| 错误成本 | 漏报损失客户，误报浪费优惠且打扰客户 |

多数类基线回答“永远预测不流失有多好”。概率基线还应输出训练集流失率，供 Log Loss 比较。

## 核心机制

逻辑回归先算线性分数 $z=w^Tx+b$，再用 Sigmoid 压到 0 到 1：

$$
p(y=1\mid x)=\frac{1}{1+e^{-z}}
$$

若阈值为 $t$，当 $p\ge t$ 时预测流失。训练使用二元交叉熵：

$$
L=-\frac{1}{n}\sum_i[y_i\log p_i+(1-y_i)\log(1-p_i)]
$$

它会重罚非常自信却判断错误的概率。概率含义和参数学习原理见 [概率统计](../G-AI%20%E5%9F%BA%E7%A1%80/02-%E6%A6%82%E7%8E%87%E7%BB%9F%E8%AE%A1.md)与[最大似然与最大后验](../G-AI%20%E5%9F%BA%E7%A1%80/08-%E6%9C%80%E5%A4%A7%E4%BC%BC%E7%84%B6%E4%B8%8E%E6%9C%80%E5%A4%A7%E5%90%8E%E9%AA%8C.md)。

## 最小手算

真实标签 `[1,1,0,0]`，概率 `[0.8,0.4,0.6,0.1]`。阈值 0.5 时 TP=1、FN=1、FP=1、TN=1，所以 Precision 和 Recall 都是 0.5。阈值降到 0.3 后 Recall 上升，但误报也增加。阈值改变决策，不会重新训练排序能力。

## 可执行实验

```python
from sklearn.datasets import make_classification
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import precision_score, recall_score, roc_auc_score
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

X, y = make_classification(
    n_samples=1000, weights=[0.9, 0.1], class_sep=1.2, random_state=42
)
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.3, stratify=y, random_state=42
)
model = make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000))
model.fit(X_train, y_train)
probability = model.predict_proba(X_test)[:, 1]
print("AUC", round(roc_auc_score(y_test, probability), 3))
for threshold in (0.2, 0.5, 0.8):
    prediction = probability >= threshold
    print(threshold, "precision", round(precision_score(y_test, prediction), 3),
          "recall", round(recall_score(y_test, prediction), 3),
          "selected", int(prediction.sum()))
```

通常阈值越高，触达人数和 Recall 越低，Precision 越高；具体方向仍应由验证数据确认。

## 评测与结果解释

- **Precision：** 被模型选中的人里多少真的为正。
- **Recall：** 所有正样本中找回多少。
- **ROC-AUC：** 评价排序，不能代替阈值成本。
- **PR-AUC：** 正类稀少时更聚焦正类检索质量。
- **Log Loss：** 评价完整概率，并惩罚过度自信。

在验证集按成本或容量选阈值，最后在测试集报告固定策略。若需要概率含义，再检查校准。

## 数据与泄漏风险

取消后填写的原因、未来退款和挽留结果不能作为特征。同一客户的多个月份可能跨集合造成身份记忆，应按客户或时间拆分。重采样只能在训练折内部发生。

## 工程排错

| 现象 | 可能原因 | 优先检查 |
| --- | --- | --- |
| 准确率高但抓不到正类 | 类别极不平衡 | 混淆矩阵、Recall、PR 曲线 |
| AUC 高但行动亏损 | 阈值或成本映射错误 | 收益、误报成本、容量 |
| 概率普遍过高 | 未校准或基准率漂移 | 可靠性曲线、近期正类率 |
| 线上 Recall 骤降 | 标签漂移或特征缺失 | 分时段指标、缺失率、延迟 |

## 适用与不适用场景

逻辑回归适合稳定、可解释的概率或排序基线。复杂非线性表格数据可比较树模型。目标是数值用回归；目标是为每个用户排序多个物品，则使用[推荐系统](12-推荐系统.md)方法。

## 学习收益

你应能区分类别、概率和决策，手算混淆矩阵指标，解释逻辑回归输出，并根据成本选择阈值。

## 给别人讲清楚

“分类模型先给风险排序，阈值再决定行动。模型会不会排与行动划不划算是两个问题。”
