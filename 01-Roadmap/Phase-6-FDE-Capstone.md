# 阶段 6：FDE 综合项目

## 建议周期与进入条件

**建议周期：8～12 周，每周 5～10 小时。** 时间是建议；范围应小到能交付一个完整客户结果，而不是堆砌所有 AI 技术。

进入条件是能独立构建并运行生产化 RAG 或 Agent 工作流，拥有质量、延迟、成本和安全证据，并能使用 Runbook 处理失败。还应能根据 [FDE 能力模型](../00-Guide/FDE-Competency-Model.md) 找出六个维度的证据缺口。

## 推荐深度与核心知识

目标是把技术与交付整合为 L4 证据：

领域入口：[FDE 实践](../11-FDE-Practice/FDE-Practice-MOC.md)，并结合[生产 AI](../09-Production-AI/Production-AI-MOC.md)与[安全治理](../10-AI-Safety-Governance/AI-Safety-Governance-MOC.md)完成上线、运行和交接。

- Discovery：利益相关者、用户、现有流程、异常路径、约束和待验证假设。
- 业务建模：基线、业务指标、价值、风险、采用条件和停止条件。
- PoC 范围：最小垂直切片、成功标准、非目标、时间盒和决策门。
- 企业集成：身份、权限、数据契约、API、遗留系统、审计和数据驻留。
- AI 评测：离线集、人工评审、线上指标、分群错误和持续回归。
- 上线交付：SLO、安全评审、变更管理、灰度、回滚与事故响应。
- 采用与交接：培训、反馈、Runbook、所有权、支持边界和复用资产。
- 沟通：状态、风险、决策、演示和面向技术/业务受众的价值表达。

## 必做实验

选择一个不依赖私有数据的客户型场景，寻找真实或模拟的业务赞助者，完成以下端到端交付：

1. 进行至少两轮需求访谈；记录问题、现有流程、异常、约束和相互矛盾的诉求。
2. 定义一个业务主指标、护栏指标、当前基线、PoC 成功/停止条件和明确非目标。
3. 交付一个最小垂直 PoC，并根据用户反馈至少调整一次范围或工作流。
4. 集成至少一个企业风格系统接口，包含身份、权限、审计、超时和测试替身。
5. 建立离线评测、人工验收和线上/模拟线上监控，完成安全与上线检查。
6. 执行上线或演练、回滚、Runbook 操作、培训交接和面向利益相关者的演示。

## 外部 GitHub 项目

- [MLflow](https://github.com/mlflow/mlflow)：研究实验、模型/应用版本与评测证据的追踪方式。
- [OpenFGA](https://github.com/openfga/openfga)：研究企业集成中的细粒度授权模型与检查路径。
- [DataHub](https://github.com/datahub-project/datahub)：观察元数据、数据契约、治理和企业系统集成边界。

这些项目是研究对象，不要求全部成为 Capstone 依赖；选择必须由客户场景与验收条件驱动。

## 开源实践：使用、源码跟踪、最小复刻、可选贡献

- **开源使用：** 选择一个与实际集成问题直接相关的项目，固定版本完成最小集成并记录许可、运维和退出成本。
- **源码跟踪：** 从项目公开 API 跟踪到权限判定、元数据写入或评测记录中的一条关键调用链。
- **最小复刻：** 独立实现 Capstone 所需的最小授权检查、证据记录或数据契约校验，说明为什么最终使用或不使用开源项目。
- **可选贡献：** 将交付中发现且不含客户信息的文档、测试或缺陷改进回馈上游；提交前用公开最小样例复现。

## 项目增量

创建一个独立、可公开的客户型 FDE Capstone 仓库。至少包括 Discovery 摘要、流程图、业务指标、PoC 方案、架构与决策记录、企业集成、评测、安全/上线检查、运行代码、测试、部署、Runbook、培训材料、演示脚本和复盘。若模拟客户，明确角色、假设与数据来源，不把模拟反馈表述为真实客户证明。

## 评测与复盘

比较业务基线、PoC 和最终方案，报告业务主指标、护栏指标、AI 质量、采用/任务完成、延迟、成本、可靠性和安全结果。复盘至少一次被证伪的需求假设、一次技术失败、一次范围变更和一次交接风险，并提炼可复用组件与不可泛化部分。

## 面试训练

- 用 10 分钟讲清客户问题、基线、约束、方案、结果和下一步，技术细节按追问展开。
- 回答“为什么需要 AI、为什么是该架构、为什么现在上线”，并给出替代方案。
- 处理客户要求、隐私/安全、交付期限和模型能力冲突的场景题。
- 演示一次生产故障诊断、范围谈判或上线 Go/No-Go 决策。
- 使用 STAR 或类似结构讲述失败、影响、个人责任和可量化改进，避免泄露任何私有信息。

## 退出证据

- 经版本标记的公开 Capstone 仓库，以及从干净环境复现的测试与部署记录。
- 访谈问题与脱敏摘要、流程/指标基线、PoC 范围、非目标和决策日志。
- 企业集成、评测、安全、上线/演练、回滚、Runbook、培训交接和演示证据。
- 业务与技术指标的前后对比、失败样例、范围变更和最终复盘。
- 一份开源调用链、最小复刻与“使用/不使用”的决策证据。
- 按 FDE 六维能力模型整理的面试证据包，能够区分事实、个人贡献和团队结果。

完成后回到 [路线总览](Roadmap-MOC.md) 和 [FDE 能力模型](../00-Guide/FDE-Competency-Model.md) 做证据盘点；下一轮学习应由真实项目缺口驱动，而不是继续线性增加工具。
