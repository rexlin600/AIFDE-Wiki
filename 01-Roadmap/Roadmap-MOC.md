# AI/FDE 七阶段路线

## 路线定位

本路线面向已有后端或全栈经验、希望转向 AI 应用工程与前沿部署工程（Forward Deployed Engineering，FDE）的工程师。默认每周投入 5～10 小时；各阶段周期是用于安排实验和项目的建议，不是硬期限。已有证据满足退出标准时可以跳过，项目暴露能力缺口时也应回到前一阶段补齐。

开始前建议先阅读 [AI 全局知识地图](../00-Guide/AI-Knowledge-Map.md) 和 [FDE 能力模型](../00-Guide/FDE-Competency-Model.md)。数学与 AI 基础、机器学习、深度学习、LLM、RAG、Agent、生产 AI、安全治理和 FDE 实践等领域 MOC 尚未创建，因此本任务只使用无链接领域名称，避免制造死链。

## 七阶段依赖与建议周期

| 阶段 | 建议周期 | 进入条件 | 主要项目增量 | 退出证据摘要 |
| --- | --- | --- | --- | --- |
| [阶段 0：工程基线](Phase-0-Baseline.md) | 1～2 周 | 能使用一种编程语言和 Git 完成小型任务 | `ai-engineering-playground` | 可复现的 API、本地模型与服务样例 |
| [阶段 1：AI/ML 基础](Phase-1-AI-ML-Foundations.md) | 6～8 周 | 阶段 0 退出证据，能读 Python 与基础统计图表 | `ai-foundations-labs` | 可解释的数据、训练、验证与 PyTorch 实验 |
| [阶段 2：LLM 工程](Phase-2-LLM-Engineering.md) | 6～8 周 | 理解过拟合、损失、梯度和基本神经网络 | `llm-engineering-lab` | 可比较模型调用、结构化输出、适配与推理 |
| [阶段 3：RAG 工程](Phase-3-RAG-Engineering.md) | 8～12 周 | 能稳定调用 LLM、生成 Embedding 并设计评测 | `production-rag-system` | 四类 RAG 对比及质量、引用、成本、延迟报告 |
| [阶段 4：Agent 工程](Phase-4-Agent-Engineering.md) | 8～12 周 | 能设计受控工具接口，并理解 RAG 的失败模式 | `enterprise-workflow-agent` | 含状态、审批、恢复、Trace 与 Agent Eval 的工作流 |
| [阶段 5：生产 AI](Phase-5-Production-AI.md) | 6～10 周 | 已有可端到端运行的 RAG 或 Agent 项目 | 对既有项目生产加固 | SLO、安全、负载、部署、回滚和运行证据 |
| [阶段 6：FDE 综合项目](Phase-6-FDE-Capstone.md) | 8～12 周 | 能独立构建并运行生产化 AI 工作流 | 客户型 FDE Capstone | 从发现、PoC 到上线、交接与演示的完整证据包 |

默认依赖是 `阶段 0 → 1 → 2 → 3 → 4 → 5 → 6`。阶段 3 与阶段 4 在满足进入条件后可以交换或部分并行；生产可靠性、安全、评测、开源研究和面试表达从阶段 0 起贯穿全程，不能推迟到最后补做。

## 每阶段固定闭环

每一阶段都必须完成以下闭环：

1. **概念：** 能用自己的语言说明机制、边界和取舍，达到该阶段的推荐深度。
2. **最小实验：** 用最少变量验证一个可证伪假设，固定环境、数据与随机种子。
3. **开源使用/源码跟踪/最小复刻：** 先运行真实项目，再跟踪关键调用链，然后脱离框架复刻核心机制；可选贡献只在证据充分时进行。
4. **项目增量：** 把实验中有效的能力接入阶段项目，添加测试、运行命令和版本记录。
5. **评测/复盘：** 同时报告质量、失败样例、延迟、成本和适用边界，记录下一次决策条件。
6. **面试表达：** 练习定义、方案设计、故障追问和项目答辩，并用仓库中的可核验证据支撑回答。

## 横向开源实践要求

开源不是单独阶段。每个阶段至少选择一个外部 GitHub 项目完成四层实践：

- **开源使用：** 固定版本运行官方最小示例，记录环境、命令、输入输出和许可证。
- **源码跟踪：** 从公开入口沿一条关键调用链追到核心实现，画出模块、数据结构与错误路径。
- **最小复刻：** 不复制项目实现，独立写出能说明核心机制的小版本，并用对照测试解释差异。
- **可选贡献：** 先复现公开 Issue，再提交文档、测试或小修复；贡献不是退出阶段的硬条件，质量高于数量。

开源记录必须链接到仓库、固定 Commit 或 Release，并区分事实、实验观察和个人推断。不要把阅读 README 当成源码研究，也不要为了贡献数量提交低价值改动。

## 横向评测与复盘要求

- 为项目保存最小回归集、运行环境、关键配置和可重复命令。
- 指标至少覆盖任务质量、错误分类、延迟和成本；涉及检索、Agent 或生产系统时增加对应专项指标。
- 每阶段至少记录一次失败实验，说明假设、结果、根因、决策和后续触发条件。
- 安全与隐私按最小权限处理；公开仓库不得出现密钥、客户数据、账号信息或前雇主私有信息。
- 实战代码放在独立 GitHub 仓库，本 Wiki 只保存项目档案、研究结论与证据链接。

## 横向面试训练要求

每阶段准备四类表达：60 秒概念解释、15 分钟系统设计、一次失败排查和一个项目证据故事。回答应包含目标与约束、候选方案、选择理由、量化结果、失败模式和下一步，而不是只罗列工具名。

阶段退出时，使用 [FDE 能力模型](../00-Guide/FDE-Competency-Model.md) 标注新增证据对应的维度和等级。若不能展示代码版本、实验结果、评测数据或交付物，就不把“学习过”视为阶段完成。
