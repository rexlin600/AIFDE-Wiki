# 混合精度与分布式训练

<!-- markdownlint-disable MD012 MD013 -->

## 它解决什么深度学习问题

模型或批量大到单设备训练太慢、显存装不下时，需要减少每个数的存储和计算成本，或让多台设备共同训练。混合精度解决“每次计算多贵”，分布式训练解决“计算和状态放在哪里”。

## 不理解会造成什么错误

- 把模型全部转成 FP16，造成梯度下溢或损失溢出。
- 多卡后仍用原来的“每卡批大小”理解总批量和学习率。
- 误以为 DDP 自动拆分输入，导致各进程读取相同样本。
- 只计计算时间，不计数据读取、梯度通信和编译预热。

## 它在训练系统中的位置

先用[PyTorch 模型训练](<10-PyTorch 模型训练.md>)得到正确的单设备 FP32 基线，再引入自动混合精度，最后才扩展到多进程。任何扩展都必须保持损失定义、有效批量和验证指标可比。

## 从图像分类扩容开始

任务输入为 `[B,C,H,W]` 图像，输出 `[B,K]` 类别 Logits。单卡批量 32、四卡数据并行时，全局批量通常为 $32\times4=128$。如果做 2 次梯度累积，有效批量变为 256。扩容成功不只看吞吐，还要保证验证精度与单卡基线在可接受容差内。

## 先建立简单基线

记录单设备 FP32 的每步时间、峰值内存、每秒样本数和验证指标。没有这个基线，就无法判断 AMP 或多卡究竟是加速了训练，还是改变了优化问题。

## 浮点精度为什么影响梯度

浮点数能表达的范围和有效位数有限。FP16 占用更少、在适合的硬件上更快，但很小的数会舍入为 0。自动混合精度让矩阵乘法等算子用低精度，让归约或敏感算子保留较高精度，而不是把所有算子统一降精度。

## 梯度缩放推导

设真实损失为 $L$，缩放因子为 $S$。反向传播缩放后的损失：

$$
L'=SL
$$

根据求导线性性：

$$
\nabla_\theta L'=S\nabla_\theta L
$$

小梯度先乘 $S$，更不容易在低精度中变成 0。优化器更新前再除以 $S$：

$$
\frac{1}{S}\nabla_\theta L'=\nabla_\theta L
$$

因此理想情况下更新不变。动态 GradScaler 遇到 Inf 或 NaN 会跳过更新并降低尺度。

## 数据并行怎样保持同一目标

第 $r$ 个进程计算本地平均梯度 $g_r$。同步数据并行做 All-Reduce 后取平均：

$$
g=\frac{1}{R}\sum_{r=1}^{R}g_r
$$

若每个进程批量相同，它等价于在全局批量上求平均损失的梯度。若损失使用求和、各进程样本数不同或梯度累积步数不同，等价关系需要重新核对。

## 最小手算

两张卡各得到梯度 `[2,4]` 和 `[6,0]`，同步平均后两张卡都使用 `[4,2]` 更新。若误做求和得到 `[8,4]`，等价学习率扩大了两倍。

真实梯度 $10^{-8}$ 在 FP16 中可能下溢。用 $S=1024$ 得到约 $10^{-5}$ 的缩放梯度，反向后再除以 1024，恢复原量级。

## NumPy 精度实验

```python
import numpy as np

gradient = np.array([1e-8, 2e-8, 5e-8], dtype=np.float32)
direct = gradient.astype(np.float16).astype(np.float32)
scale = 1024.0
scaled = (gradient * scale).astype(np.float16).astype(np.float32) / scale
print("direct", direct)
print("scaled then unscaled", scaled)
print("two-rank mean", np.mean([[2.0, 4.0], [6.0, 0.0]], axis=0))
```

这个实验只说明数值表示，不代表 CPU 上混合精度会加速。

## PyTorch 语义实验

```python
import torch

torch.manual_seed(42)
model = torch.nn.Linear(4, 2)
optimizer = torch.optim.SGD(model.parameters(), lr=0.1)
x = torch.randn(8, 4)
y = torch.randint(0, 2, (8,))
optimizer.zero_grad(set_to_none=True)
with torch.autocast(device_type="cpu", dtype=torch.bfloat16):
    logits = model(x)
    loss = torch.nn.functional.cross_entropy(logits, y)
loss.backward()
optimizer.step()
print(logits.dtype, round(loss.item(), 4))
print("CUDA available", torch.cuda.is_available())
```

CPU 示例验证 `autocast` 的作用域和梯度流程。GPU FP16 训练通常还需 `torch.amp.GradScaler`；没有 CUDA 时不应声称测得显存或吞吐收益。

## 实验结果解释

数值相近不要求逐位相同。验收应比较验证指标、损失曲线和收敛步数，而不是要求 FP32 与 AMP 每步完全一致。分布式加速还要区分强扩展和弱扩展，并扣除数据与通信等待。

## 训练与推理差异

训练要保存梯度、优化器状态并进行跨进程同步；推理通常不需要反向与优化器，可采用不同精度和并行策略。训练检查点只由指定进程写入，恢复时要正确设置设备映射并保证所有进程状态一致。

## 数据与验证风险

`DistributedSampler` 负责让不同进程读取不同样本，每轮通常需要更新 epoch 以改变洗牌。验证指标必须跨进程汇总分子和分母，不能简单平均不同样本数进程的局部百分比。

## 工程排错

| 现象 | 可能原因 | 优先检查 |
| --- | --- | --- |
| AMP 后损失 NaN | 溢出或不稳定算子 | GradScaler、首个非有限张量、FP32 基线 |
| 多卡精度变化 | 有效批量或损失归约改变 | 每卡批量、累积步数、mean 与 sum |
| 多卡没有加速 | 通信或输入成为瓶颈 | 每步时间分解、GPU 利用率、批量 |
| 训练进程卡死 | 各 rank 控制流或集合通信不一致 | rank 日志、超时、数据长度 |
| 恢复后结果不同 | RNG 或优化器状态缺失 | 检查点字段、sampler epoch、设备映射 |

## 适用与不适用场景

AMP 适合矩阵计算占主导且硬件支持低精度的模型；很小模型或 CPU 工作负载未必获益。DDP 适合单设备基线正确后扩大吞吐，不解决单卡放不下完整模型的问题，后者可能需要参数、梯度或优化器状态分片。

## 学习收益

你应能推导梯度缩放和数据并行平均，计算有效批量，区分计算与通信瓶颈，并为 AMP 和多卡建立可比较基线。

## 给别人讲清楚

“混合精度让合适的计算用更便宜的数字表示，梯度缩放保护太小的梯度；数据并行让多份模型各看一批数据，再把梯度平均成同一次更新。”
