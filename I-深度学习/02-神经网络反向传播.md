# 神经网络反向传播

<!-- markdownlint-disable MD013 -->

## 它解决什么深度学习问题

训练模型必须回答：最终分类错了以后，每个参数应向哪个方向改变、改变多少？反向传播把损失对输出的影响，沿计算图从后向前传递，高效求得所有参数的梯度。

它不是一种优化器。反向传播负责“算梯度”，SGD 或 Adam 等优化器负责“用梯度更新参数”。

## 不理解会造成什么错误

- 忘记 `zero_grad()`，不同批次的梯度意外累加。
- 在 NumPy 转换、`.item()` 或 `detach()` 处切断计算图。
- 原地修改反向传播所需张量，引发版本错误或错误梯度。
- 看到损失下降就相信梯度，实现自定义计算时不做数值检查。

## 它在训练系统中的位置

前向传播记录计算关系并产生标量损失；反向传播从损失的梯度 1 出发，应用局部导数和链式法则；优化器读取叶子参数的 `.grad`。

```text
参数 → 前向计算 → 损失
 ↑                 │
 └── 优化器 ← 梯度 ←┘
```

## 从分类错误如何传回参数开始

对一批手写形状，MLP 输出 `[B,C]` logits，交叉熵得到一个标量。业务真正需要的不是“损失为 0.8”，而是让数万个参数各自得到调整信号。反向传播通过复用前向中间结果，一次反向遍历完成这个任务。

## 先建立简单基线

最简单的方法是有限差分：每次把一个参数增加和减少很小的 $\varepsilon$，观察损失变化。它容易理解但每个参数都需额外前向计算，只适合检查少量梯度。反向传播的成本通常只是若干次前向计算的量级。

## 张量形状与数据流

仍以两层 MLP 为例：

| 梯度 | 形状 | 含义 |
| --- | --- | --- |
| $\partial L/\partial Z_2$ | `[B,C]` | 每个 logit 对损失的影响 |
| $\partial L/\partial W_2$ | `[H,C]` | 第二层每个权重的影响 |
| $\partial L/\partial A_1$ | `[B,H]` | 传回隐藏表示的影响 |
| $\partial L/\partial W_1$ | `[D,H]` | 第一层每个权重的影响 |

梯度与它所描述的变量形状相同。批次样本共享参数，所以参数梯度会沿批次轴求和或求平均。

## 链式法则怎样工作

先看标量计算图：

$$
u=wx,\qquad a=u+b,\qquad \hat y=a^2,\qquad
L=\frac12(\hat y-y)^2
$$

每个节点只需知道自己的局部导数：

$$
\frac{\partial L}{\partial \hat y}=\hat y-y,\quad
\frac{\partial \hat y}{\partial a}=2a,\quad
\frac{\partial a}{\partial u}=1,\quad
\frac{\partial u}{\partial w}=x
$$

将路径上的局部导数相乘：

$$
\frac{\partial L}{\partial w}
=(\hat y-y)\cdot2a\cdot1\cdot x
$$

如果同一个变量通过多条路径影响损失，各路径贡献相加。这正是计算图分叉处发生梯度累积的原因。

## Softmax 与交叉熵的梯度

单样本 one-hot 标签记为 $y_c$，损失 $L=-\sum_c y_c\log p_c$。Softmax 的导数为：

$$
\frac{\partial p_j}{\partial z_k}=p_j(\mathbf 1[j=k]-p_k)
$$

代入链式法则并利用 $y$ 只有真实类为 1，可化简为：

$$
\frac{\partial L}{\partial z_k}=p_k-y_k
$$

直觉是：预测概率高于目标的类得到正梯度，梯度下降会压低其 logit；真实类概率低于 1，得到负梯度，更新会抬高它。

## 最小手算

令 $w=2,x=3,b=-1,y=16$。则 $u=6$，$a=5$，$\hat y=25$，$L=(25-16)^2/2=40.5$。

$$
\frac{\partial L}{\partial w}=9\times10\times3=270,\qquad
\frac{\partial L}{\partial b}=9\times10=90
$$

梯度很大并非一定错误；它表示当前函数在参数附近非常陡。应结合学习率判断更新是否过大。

## NumPy 复刻与有限差分检查

```python
import numpy as np

np.random.seed(11)
x, w, b, y = 3.0, 2.0, -1.0, 16.0

def loss_fn(weight, bias):
    prediction = (weight * x + bias) ** 2
    return 0.5 * (prediction - y) ** 2

a = w * x + b
prediction = a**2
grad_w = (prediction - y) * 2 * a * x
grad_b = (prediction - y) * 2 * a

eps = 1e-5
numeric_w = (loss_fn(w + eps, b) - loss_fn(w - eps, b)) / (2 * eps)
numeric_b = (loss_fn(w, b + eps) - loss_fn(w, b - eps)) / (2 * eps)
assert np.isclose(grad_w, 270.0)
assert np.isclose(grad_b, 90.0)
assert np.allclose([grad_w, grad_b], [numeric_w, numeric_b], rtol=1e-6)
print("analytic:", grad_w, grad_b, "numeric:", numeric_w, numeric_b)
```

中心差分的误差通常为 $O(\varepsilon^2)$，但 $\varepsilon$ 过小又会放大浮点舍入误差，所以梯度检查应使用双精度和适中的步长。

## PyTorch Autograd 对照

```python
import torch

torch.manual_seed(11)
x = torch.tensor(3.0, dtype=torch.float64)
w = torch.tensor(2.0, dtype=torch.float64, requires_grad=True)
b = torch.tensor(-1.0, dtype=torch.float64, requires_grad=True)
y = torch.tensor(16.0, dtype=torch.float64)

prediction = (w * x + b) ** 2
loss = 0.5 * (prediction - y) ** 2
loss.backward()
assert torch.allclose(w.grad, torch.tensor(270.0, dtype=torch.float64))
assert torch.allclose(b.grad, torch.tensor(90.0, dtype=torch.float64))

# backward 再调用一次会累加到已有 .grad，因此先清零。
w.grad.zero_()
b.grad.zero_()
loss = 0.5 * ((w * x + b) ** 2 - y) ** 2
loss.backward()
assert w.grad.item() == 270.0
print("loss:", loss.item(), "grad_w:", w.grad.item())
```

## 如何解释实验结果

解析梯度、有限差分和 Autograd 一致，是这段计算局部正确的强证据。它仍不能保证整个训练系统正确：错误标签、错误损失缩放和泄漏都可能产生数学上正确但业务上无意义的梯度。

## 训练与推理差异

训练时 PyTorch 为 `requires_grad=True` 的运算建立动态图，`backward()` 后中间图默认释放。推理时使用 `torch.inference_mode()`，减少保存中间状态的开销。`model.eval()` 管理模块行为，不能替代关闭梯度；两者职责不同。

## 数据与验证风险

反向传播只优化提供给它的目标。如果标签含未来信息、训练验证对象重叠，梯度会非常有效地学习泄漏。梯度正确不等于目标正确。拆分和指标边界参见[数据泄漏](../H-机器学习/05-数据泄漏.md)与[指标](../H-机器学习/06-指标.md)。

## 工程排错

| 现象 | 可能原因 | 优先检查 |
| --- | --- | --- |
| 参数 `.grad` 为 `None` | 参数未参与损失或计算图被切断 | 沿前向路径检查 `requires_grad` 与 `detach` |
| 梯度一直为零 | 激活饱和、ReLU 全关闭或错误掩码 | 记录逐层激活和梯度比例 |
| 梯度越来越大 | 深链乘积、学习率高或输入未缩放 | 检查梯度范数和有限值 |
| 第二批更新异常大 | 忘记清空梯度 | 确认每步更新前调用 `zero_grad` |
| 自定义公式训练异常 | 局部导数或广播求和错误 | 用双精度中心差分检查小张量 |

## 适用与不适用场景

反向传播适用于可微或几乎处处可微的计算图。离散采样、硬阈值和外部不可微程序不能直接传梯度，需要可微近似、策略梯度或其他估计方法。即使可微，极长路径也可能造成梯度消失或爆炸。

## 学习收益

读完后应能区分反向传播与优化器，沿简单计算图写出局部导数，解释梯度相乘与相加，使用有限差分检查实现，并正确管理 PyTorch 的梯度生命周期。

## 给别人讲清楚

反向传播像从最终账单向前追责：每一步只回答“上游结果变化一点，我这里会变化多少”，把这些局部比例沿路径相乘；若有多条影响路径，再把责任相加。
