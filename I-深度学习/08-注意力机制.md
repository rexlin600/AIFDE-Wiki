# 注意力机制

<!-- markdownlint-disable MD012 MD013 -->

## 它解决什么深度学习问题

注意力让每个位置根据当前内容，从其他位置动态取回相关信息。句子中代词可以关注它指代的名词，故障时间点可以关注较早出现的异常信号。与把整个过去压进单个循环状态不同，注意力保留所有位置并直接建立两两联系。

本篇统一使用序列 `[B,T,D]`，多头中间张量使用 `[B,H,T,d_k]`，且 $D=H d_k$。

## 不理解会造成什么错误

- 把 Padding Mask 和因果 Mask 混为一谈，导致模型读取填充值或未来答案。
- 忘记除以 $\sqrt{d_k}$，大维度下 Softmax 过早饱和、梯度变小。
- 多头重排时把序列维与头维混合，结果形状虽能运行但语义错误。
- 看到注意力权重很高，就断言该位置是因果解释。
- 忽略自注意力的 $T^2$ 内存与计算增长。

## 它在训练系统中的位置

输入表示先线性投影为 Query、Key、Value，注意力产生同形状的上下文表示，再交给残差、归一化和前馈网络。注意力是[Transformer](09-Transformer.md)的核心部件，但注意力本身不是完整模型。

## 从告警事件归因开始

给定一段不等长设备事件，模型为每个时刻判断是否即将故障：

- 输入：事件嵌入 `[B,T,D]`；
- 输出：每个时刻的上下文 `[B,T,D]`；
- 标签：逐时刻风险；
- Mask：Padding 不可见，在线预测还需屏蔽未来；
- 指标：逐时刻召回、误报和提前量。

关键业务问题不是“注意力图好不好看”，而是它是否在严格时间验证中改善预警，同时满足延迟和内存预算。

## 先建立简单基线

先比较最近一步、窗口平均和 LSTM。平均池化没有内容选择，LSTM 用递归状态聚合；只有当跨位置的动态关联带来稳定收益时，注意力的额外成本才合理。

## Query Key Value 的直觉

- Query 表示“当前位置想找什么”；
- Key 表示“每个位置可被怎样匹配”；
- Value 表示“匹配后真正取回什么”。

投影为：

$$
Q=XW_Q,\qquad K=XW_K,\qquad V=XW_V
$$

若 $X$ 为 `[B,T,D]`，单头 $Q,K,V$ 为 `[B,T,d_k]`。相似度和输出为：

$$
S=\frac{QK^{\mathsf T}}{\sqrt{d_k}},\qquad
A=\operatorname{softmax}(S+M),\qquad
O=AV
$$

$S$ 和 $A$ 为 `[B,T,T]`，最后一维表示每个 Query 对所有 Key 的分布；$O$ 为 `[B,T,d_v]`。加法 Mask $M$ 在允许位置取 0，在禁止位置取 $-\infty$。

## 为什么缩放点积要除以根号维度

假设 $q_i$ 与 $k_i$ 独立、均值为 0、方差为 1。点积为
$s=\sum_{i=1}^{d_k}q_i k_i$。每一项的均值为 0、方差为 1，因此独立相加后：

$$
\operatorname{Var}(s)=\sum_{i=1}^{d_k}\operatorname{Var}(q_i k_i)=d_k
$$

标准差随 $\sqrt{d_k}$ 增长。除以 $\sqrt{d_k}$ 后：

$$
\operatorname{Var}\left(\frac{s}{\sqrt{d_k}}\right)=1
$$

这让不同头维下的分数尺度更稳定，避免 Softmax 输入过大而接近 one-hot。该推导依赖简化的独立同分布假设，但准确说明了缩放目的。

## Softmax 为什么形成加权平均

对某个 Query 的分数 $s_j$：

$$
a_j=\frac{e^{s_j}}{\sum_m e^{s_m}}
$$

所以 $a_j>0$ 且 $\sum_j a_j=1$。输出 $o=\sum_j a_jv_j$ 是 Value 的凸组合。数值计算应先减去行最大值，参见[数值稳定性](../G-AI%20基础/05-数值稳定性.md)。

## 多头注意力的形状

一次投影得到 `[B,T,H*d_k]`，然后：

```text
[B,T,H*d_k]
→ reshape [B,T,H,d_k]
→ transpose [B,H,T,d_k]
→ 每个头独立计算 [B,H,T,T]
→ 得到 [B,H,T,d_k]
→ transpose 并拼接 [B,T,H*d_k]
→ 输出投影 [B,T,D]
```

多个头允许模型在不同表示子空间建立关系，但不保证每个头都会学出人类可命名的模式。

## 最小手算

令一个 Query 为 $q=[1,0]$，两个 Key 为 $k_1=[1,0]$、$k_2=[0,1]$，Value 为 $v_1=[2,0]$、$v_2=[0,4]$。$d_k=2$，分数为 $[1/\sqrt2,0]$。

Softmax 权重约为 `[0.670,0.330]`，输出为：

$$
o=0.670[2,0]+0.330[0,4]\approx[1.340,1.321]
$$

若屏蔽第二个 Key，其分数变为负无穷，权重成为 `[1,0]`，输出就是 `[2,0]`。

## NumPy 复刻缩放点积与 Mask

```python
import numpy as np

np.random.seed(42)
q = np.array([[[1., 0.], [0., 1.], [1., 1.]]])  # [B=1,T=3,d=2]
k = q.copy()
v = np.array([[[2., 0.], [0., 4.], [3., 3.]]])
scores = q @ k.transpose(0, 2, 1) / np.sqrt(q.shape[-1])
causal = np.triu(np.ones((3, 3), dtype=bool), k=1)
masked_scores = np.where(causal[None], -np.inf, scores)
stable = masked_scores - np.max(masked_scores, axis=-1, keepdims=True)
weights = np.exp(stable)
weights /= weights.sum(axis=-1, keepdims=True)
out = weights @ v

assert scores.shape == (1, 3, 3)
assert out.shape == (1, 3, 2)
assert np.all(weights[0][causal] == 0.0)
assert np.allclose(weights.sum(axis=-1), 1.0)
assert np.allclose(out[0, 0], v[0, 0])
print("weights\n", np.round(weights[0], 3))
```

第一位置只能看自己，断言直接验证了被 Mask 的权重为零，而不是仅凭图形猜测。

## PyTorch 等价实验

```python
import numpy as np
import torch
import torch.nn.functional as F

np.random.seed(42)
torch.manual_seed(42)
q_np = np.array([[[1., 0.], [0., 1.], [1., 1.]]], dtype=np.float32)
v_np = np.array([[[2., 0.], [0., 4.], [3., 3.]]], dtype=np.float32)
k_np = q_np.copy()

scores = q_np @ k_np.transpose(0, 2, 1) / np.sqrt(2.0)
blocked = np.triu(np.ones((3, 3), dtype=bool), k=1)
scores = np.where(blocked[None], -np.inf, scores)
weights = np.exp(scores - np.max(scores, axis=-1, keepdims=True))
weights /= weights.sum(axis=-1, keepdims=True)
manual = weights @ v_np

# PyTorch 接收 [B,H,T,d]；浮点 Mask 中 -inf 表示禁止位置。
q = torch.tensor(q_np)[:, None]
k = torch.tensor(k_np)[:, None]
v = torch.tensor(v_np)[:, None]
mask = torch.zeros(3, 3).masked_fill(torch.tensor(blocked), float("-inf"))
actual = F.scaled_dot_product_attention(q, k, v, attn_mask=mask)

assert tuple(actual.shape) == (1, 1, 3, 2)
assert np.allclose(actual[:, 0].numpy(), manual, atol=1e-6)
assert np.all(weights[0][blocked] == 0.0)
print("max difference", np.max(np.abs(actual[:, 0].numpy() - manual)))
```

## 两类 Mask 必须分清

- **Padding Mask：** 每个样本不同，禁止关注补齐位置，概念形状常为 `[B,T]`，再广播到注意力分数。
- **因果 Mask：** 每个 Query 只能看自己和过去，形状常为 `[T,T]` 的上三角屏蔽矩阵。

不同 PyTorch API 对布尔 Mask 的 `True` 含义可能不同。不要凭记忆混用；阅读所调用函数的文档，并用“被屏蔽权重为零、改动未来 Value 不影响过去输出”的断言验证语义。

## 实验结果怎样解释

两个实现数值一致，说明缩放、Softmax、加法 Mask 和 Value 聚合在此例中对齐。它没有证明注意力权重等同于可靠解释，也没有测量长序列性能。真实模型需比较任务指标、显存、时延及不同长度切片。

## 训练与推理差异

注意力模块中的 Dropout 通常在 `eval()` 后关闭，但函数式 `scaled_dot_product_attention` 是一个重要特例：它始终按传入的 `dropout_p` 执行 Dropout，调用方必须在推理时显式传入 `0.0`。自回归推理每次只新增一个位置，通常缓存过去的 Key 和 Value，避免重复计算；训练则可并行处理完整序列，但必须应用因果 Mask。缓存会改变内存与形状管理，不改变数学目标。

## 数据与验证风险

- 在线任务必须按真实时间构造因果输入，不能仅靠模型内 Mask 掩盖未来特征泄漏。
- Padding、截断和标签位置应使用同一长度定义。
- 位置特征若包含事后修订时间，会绕过注意力 Mask 泄漏。
- 在短序列上胜出不能推出长序列可用，应按长度报告效果和峰值内存。
- 注意力图只能作为诊断线索，不能单独支撑业务因果结论。

## 工程排错

| 现象 | 可能原因 | 优先检查 |
| --- | --- | --- |
| 训练损失异常低 | 因果 Mask 方向反了 | 修改未来 Value，断言过去输出不变 |
| Padding 位置有权重 | Mask 未广播到 Key 维 | 打印分数和权重形状 |
| Softmax 接近 one-hot | 遗漏 $\sqrt{d_k}$ 缩放 | 分数标准差、缩放位置 |
| 多头输出错乱 | reshape 后未转置 | 逐步核对 `[B,H,T,d_k]` |
| 长序列显存暴涨 | 保存了 `[T,T]` 分数 | 序列长度、注意力实现和峰值内存 |
| 推理结果不稳定 | Dropout 未关闭 | `eval`、随机种子、Mask 类型 |

## 适用与不适用场景

注意力适合相关位置相距较远、需要内容自适应聚合和训练并行的任务。序列很长且资源有限时，标准全注意力的二次复杂度可能不可接受；短流式任务用 RNN/LSTM 可能更简单；局部空间模式强的视觉任务先比较[CNN](06-卷积神经网络%20CNN.md)。

## 学习收益

你应能从 QKV 推到缩放点积，解释 $\sqrt{d_k}$，追踪多头形状，区分 Padding 与因果 Mask，并用断言验证不可见性。

## 给别人讲清楚

“Query 提问题，Key 用来匹配，Value 提供答案。模型把匹配分数归一化后对答案加权平均；Mask 则明确哪些答案根本不允许看到。”

## 自检问题

1. 为什么点积方差随 $d_k$ 增长？
2. Softmax 为什么使输出成为 Value 的加权平均？
3. Padding Mask 与因果 Mask 分别阻止什么？
4. 为什么注意力权重不能直接视为因果解释？
