# 批处理与模型序列化

<!-- markdownlint-disable MD013 -->

## 它解决什么深度学习问题

真实文本、语音和事件序列长度不同，而硬件擅长处理规则张量。批处理用 Padding 把样本对齐，用 Mask 阻止填充值参与计算；模型序列化则把训练所得状态保存下来，使模型能够部署、复现实验并从中断处继续。

这两个问题共同决定“训练时看到的模型”能否成为“恢复后仍给出相同结果的推理工件”。

## 不理解会造成什么错误

- 把 Padding 当成真实 token，短样本表示随批内最长长度改变。
- Mask 的真假语义或形状传反，模型只关注填充位置。
- 直接平均所有位置，让补零稀释短序列特征。
- 保存整个 Python 模型对象，使工件依赖原始类路径和代码环境。
- 只保存权重却声称可以无缝续训，实际丢失优化器动量和训练步数。
- 恢复后忘记 `eval()`，相同输入得到不同输出。

## 它在训练系统中的位置

```text
不同长度样本
→ collate_fn
→ padded [B,T,D] + padding_mask [B,T]
→ 模型只聚合有效位置
→ state_dict + 配置 + 优化器状态
→ 恢复、验证一致性、部署或续训
```

批整理位于 Dataset 和模型之间；序列化位于训练、故障恢复和部署之间。二者都必须保留明确的数据契约。

## 从一个 AI 案例开始

假设根据设备最近若干次事件预测是否需要维护：

- 单条事件序列长度不同，每个事件有 $D=3$ 个特征；
- 批处理后输入是 `[B,T,3]`；
- `padding_mask` 是 `[B,T]`，本文约定 `True` 表示填充位置；
- 模型对有效事件做聚合，输出 `[B,2]` 的维护类别 logits；
- 漏报维护的成本高于误报，应在独立验证集上选择决策阈值。

## 先建立简单基线

第一版不必立即使用 RNN 或 Transformer。先对有效事件做 Masked Mean，再接线性分类器。它忽略顺序，但容易检查：若这个基线都失败，应先检查事件、标签、Mask 和拆分。

## 张量形状与数据流

三条长度分别为 2、4、3 的序列，批内最长长度 $T=4$：

```text
原始样本       [2,D] [4,D] [3,D]
Padding 后     x [B=3,T=4,D]
填充位置       padding_mask [3,4]
有效位置       valid = ~padding_mask → [3,4]
加权求和       (x * valid[...,None]).sum(1) → [3,D]
除以有效长度   pooled [3,D]
线性分类       logits [3,2]
```

在 PyTorch 的常见注意力接口中，布尔 `key_padding_mask=True` 也通常表示该位置应被忽略。不同 API 可能使用相反约定，传入前必须查接口并用小例子验证。

## Padding 与 Mask 核心机制

设第 $i$ 条序列长度为 $L_i$，批内最大长度为 $T=\max_i L_i$。Padding 后：

$$
\tilde x_{i,t}=\begin{cases}
x_{i,t},&t<L_i\\
0,&t\ge L_i
\end{cases}
$$

定义有效位 Mask 为 $m_{i,t}=1$ 当 $t<L_i$，否则为 0。Masked Mean 是：

$$
h_i=\frac{\sum_{t=0}^{T-1}m_{i,t}\tilde x_{i,t}}
{\sum_{t=0}^{T-1}m_{i,t}}
$$

分母必须是有效长度 $L_i$，不能使用批内最大长度 $T$。即使填充值是零，除错分母仍会缩小短序列表示。

Padding 的元素开销为 $B\times T\times D$。把相近长度样本放入同一批可以减少无效计算，但若按长度排序破坏了时间或样本随机性，要通过分桶采样器明确控制。

## 最小手算

两条一维序列为 `[2,4]` 和 `[1,3,5]`。Padding 后：

$$
X=\begin{bmatrix}2&4&0\\1&3&5\end{bmatrix},\qquad
M=\begin{bmatrix}1&1&0\\1&1&1\end{bmatrix}
$$

Masked Mean 分别为 $(2+4)/2=3$ 和 $(1+3+5)/3=3$。若错误地都除以 $T=3$，第一条会变成 2，说明补零虽不进入分子，仍能通过错误分母污染结果。

## state_dict 与检查点

`model.state_dict()` 是参数和持久缓冲区名称到张量的映射。它不包含模型类的 Python 结构，因此恢复时要先用同一配置构造模型，再调用 `load_state_dict()`。

| 用途 | 至少保存的状态 |
| --- | --- |
| 仅推理 | 模型 `state_dict`、模型配置、词表或预处理版本 |
| 继续训练 | 上述内容、优化器、调度器、epoch/step、随机数状态 |
| 选择最佳模型 | 上述内容、验证指标、选择规则、数据版本 |

模型权重是工件的一部分，不是完整工件。类别映射、Padding 值、Mask 语义和特征归一化都必须版本化。

## 可执行 CPU 实验

下面自定义 `collate_fn` 生成 Padding 与 Mask，训练一个 Masked Mean 分类器，再通过内存缓冲区完成 `state_dict` 往返。无需创建临时文件。

```python
import io
import random
import numpy as np
import torch
from torch import nn
from torch.nn.utils.rnn import pad_sequence
from torch.utils.data import DataLoader, Dataset

SEED = 42
random.seed(SEED)
np.random.seed(SEED)
torch.manual_seed(SEED)

class EventDataset(Dataset):
    def __init__(self, count=80):
        generator = torch.Generator().manual_seed(SEED)
        self.samples = []
        for index in range(count):
            length = 2 + index % 5
            sequence = torch.randn(length, 3, generator=generator)
            label = int(sequence[:, 0].mean() > 0)
            self.samples.append((sequence, label))

    def __len__(self):
        return len(self.samples)

    def __getitem__(self, index):
        return self.samples[index]

def collate_events(batch):
    sequences, labels = zip(*batch)
    lengths = torch.tensor([sequence.size(0) for sequence in sequences])
    padded = pad_sequence(sequences, batch_first=True, padding_value=0.0)
    positions = torch.arange(padded.size(1)).unsqueeze(0)
    padding_mask = positions >= lengths.unsqueeze(1)  # True 表示忽略
    return padded, padding_mask, torch.tensor(labels)

class MaskedMeanClassifier(nn.Module):
    def __init__(self, input_dim=3, classes=2):
        super().__init__()
        self.classifier = nn.Linear(input_dim, classes)

    def forward(self, padded, padding_mask):
        valid = (~padding_mask).unsqueeze(-1).to(padded.dtype)
        lengths = valid.sum(dim=1).clamp_min(1.0)
        pooled = (padded * valid).sum(dim=1) / lengths
        return self.classifier(pooled)

dataset = EventDataset()
loader = DataLoader(dataset, batch_size=16, shuffle=True,
                    collate_fn=collate_events,
                    generator=torch.Generator().manual_seed(SEED))
model = MaskedMeanClassifier()
optimizer = torch.optim.Adam(model.parameters(), lr=0.08)
criterion = nn.CrossEntropyLoss()

for epoch in range(30):
    model.train()
    for padded, padding_mask, labels in loader:
        optimizer.zero_grad(set_to_none=True)
        logits = model(padded, padding_mask)
        loss = criterion(logits, labels)
        loss.backward()
        optimizer.step()

# 固定探针，同时验证 Mask 形状和恢复前输出。
probe_sequences = [dataset[0], dataset[3], dataset[7]]
probe_x, probe_mask, probe_y = collate_events(probe_sequences)
assert probe_x.shape == (3, 5, 3)
assert probe_mask.shape == (3, 5)
assert probe_mask[0].tolist() == [False, False, True, True, True]

model.eval()
with torch.inference_mode():
    before = model(probe_x, probe_mask)

checkpoint = {
    "model": model.state_dict(),
    "optimizer": optimizer.state_dict(),
    "epoch": epoch,
    "config": {"input_dim": 3, "classes": 2, "padding_value": 0.0},
    "torch_rng_state": torch.get_rng_state(),
}
buffer = io.BytesIO()
torch.save(checkpoint, buffer)
buffer.seek(0)
loaded = torch.load(buffer, map_location="cpu", weights_only=True)

restored = MaskedMeanClassifier(
    input_dim=loaded["config"]["input_dim"],
    classes=loaded["config"]["classes"],
)
restored.load_state_dict(loaded["model"], strict=True)
restored.eval()
with torch.inference_mode():
    after = restored(probe_x, probe_mask)

assert torch.equal(before, after)
assert loaded["epoch"] == 29
print(probe_x.shape, probe_mask.tolist())
print("round-trip max error", (before - after).abs().max().item())
```

## 实验结果解释

断言证明三件事：批整理得到预期 `[B,T,D]` 和 `[B,T]`；短序列的填充位置被正确标记；从 `state_dict` 恢复的新模型对同一探针产生完全一致的 logits。

这并不证明跨 PyTorch 版本、跨设备或不同预处理实现一定兼容。生产发布还要在目标环境加载工件并跑固定黄金样本。

## 训练与推理差异

- 训练检查点保存优化器、步数和随机状态；轻量推理工件通常只需要权重、结构配置和预处理资产。
- 训练使用 `model.train()`；恢复后推理必须显式调用 `model.eval()` 和 `torch.inference_mode()`。
- 训练批次可按长度分桶提高吞吐；在线推理还需在等待凑批和响应延迟之间取舍。
- 保存 GPU 模型后，可通过 `map_location="cpu"` 在 CPU 加载；加载后仍要把模型和输入迁移到相同设备。

## 数据与验证风险

- 按长度分桶不是随机拆分，不能让同一用户或相邻时间事件跨越数据边界。
- 截断过长序列可能删除决定标签的早期事件，要按长度分组报告指标。
- Padding 比例可能在线上变化，影响吞吐和输出分布，应纳入监控。
- 检查点选择只能使用验证集；最终测试集不参与选择 epoch。
- 反序列化不可信文件有安全风险，只加载可信来源，并优先采用权重形式和受限加载方式。

## 工程排错

| 现象 | 可能原因 | 优先检查 |
| --- | --- | --- |
| 短序列结果随批次变化 | Padding 进入聚合 | Mask 语义、分母、填充值 |
| Attention 关注填充位置 | Mask 真假或维度错误 | 构造两条小序列查看权重 |
| 批次形状偶尔报错 | `collate_fn` 未处理变长输入 | 单样本形状、`batch_first` |
| `load_state_dict` 缺少键 | 模型配置或代码版本变化 | missing/unexpected keys、`strict=True` |
| 恢复后输出不同 | 模式、权重或预处理不一致 | `eval()`、黄金输入、资产版本 |
| 续训轨迹突变 | 优化器或随机状态未恢复 | optimizer、scheduler、step、RNG |
| 推理延迟抖动 | 动态长度和批大小变化 | Padding 比例、分桶、长度上限 |

## 适用与不适用场景

Padding 加 Mask 适合长度差异可控、批量矩阵计算收益明显的任务。长度差异极大时，可考虑长度分桶、截断、滑动窗口、PackedSequence 或嵌套张量，但要核对算子支持。

`state_dict` 适合 Python/PyTorch 环境中的训练恢复和部署。需要跨语言、移动端或长期稳定格式时，应评估导出图格式和目标运行时，而不是假设 Python 检查点天然可移植。

## 学习收益

你应能为变长序列建立清晰的 Padding 与 Mask 契约，计算并控制填充开销；能区分推理权重和完整训练检查点，并用固定探针验证恢复前后的一致性。

## 给别人讲清楚

“Padding 是为了把不同长度的内容装进同一个方盒子，Mask 是告诉模型哪些只是垫片；`state_dict` 保存模型学到的数值，配置和预处理则说明这些数值该装回哪里。”
