# 深度学习训练诊断

<!-- markdownlint-disable MD013 -->

## 它解决什么深度学习问题

当损失不降、验证集变差或出现 NaN 时，继续换模型通常只会增加变量。训练诊断把“效果不好”拆成数据、前向、损失、梯度、更新和泛化六类可验证假设，并按最低成本顺序定位根因。

## 不理解会造成什么错误

- 把标签错位误判为模型容量不足。
- 梯度已经断开，却只盯着总损失曲线。
- 一上来训练全量数据，等待几小时才发现代码不能拟合 16 个样本。
- 只报告训练集指标，把过拟合当作训练成功。
- 看到 NaN 就盲目减小学习率，忽略非法输入或不稳定损失。

## 它在训练系统中的位置

```text
输入与标签检查
→ 前向形状和数值
→ 小批次过拟合
→ 梯度是否存在且有限
→ 参数是否真的更新
→ 训练验证差距
→ 性能和资源瓶颈
```

诊断贯穿训练前、训练中和上线后。它依赖[PyTorch 模型训练](10-PyTorch%20模型训练.md)中的可靠循环，并向检查点、监控和回滚提供证据。

## 从一个 AI 案例开始

假设用四个传感器特征预测设备故障，模型在训练五轮后准确率仍接近随机：

- 输入 `x` 为 `[B,4]`，标签 `y` 为 `[B]`；
- 模型输出 `[B,2]` logits；
- 训练损失是交叉熵；
- 首要问题不是“换 Transformer 会不会更好”，而是当前批次能否被一个小网络记住。

若网络连固定的 16 个样本都无法过拟合，优先怀疑数据、损失、梯度或更新实现；若能记住小批次却验证差，再调查样本量、分布差异、泄漏和正则化。

## 先建立简单基线

保存三条基线：随机或多数类损失、线性模型结果、一个固定小批次的可过拟合结果。它们分别回答标签是否有意义、非线性是否必要、训练链路是否畅通。

## 诊断顺序

### 第一步 检查数据与标签

查看形状、数据类型、最小最大值、缺失值、类别计数和若干可人工核对样本。分类标签应满足 `0 <= y < C`。确认特征和标签经过相同打乱与切分。

### 第二步 检查前向与初始损失

确认 logits 的形状是 `[B,C]`，值全部有限。均匀随机的 $C$ 分类器，其初始交叉熵通常约为 $\log C$；偏离很多不一定错误，但值得检查初始化和标签。

### 第三步 过拟合一个小批次

关闭数据增强、Dropout 和 Weight Decay，在固定 8 到 32 个干净样本上训练。足够容量的网络应把训练损失压得很低。这个测试不衡量泛化，只验证管道具备学习能力。

### 第四步 检查梯度与参数更新

逐层查看梯度是否为 `None`、是否有限、范数是否长期为零或极大；比较 `step()` 前后的参数。激活钩子可帮助发现全零 ReLU、饱和激活和异常尺度。

### 第五步 恢复真实训练并一次只加一个因素

依次恢复完整数据、增强、正则化和学习率计划。每次只改变一个因素，并记录训练与验证曲线，才能把现象归因到具体变化。

## 梯度范数与更新尺度

对第 $l$ 层参数 $\theta_l$，梯度二范数为：

$$
g_l=\lVert\nabla_{\theta_l}L\rVert_2
$$

整体梯度范数是：

$$
g=\sqrt{\sum_l g_l^2}
$$

对普通 SGD，更新量 $\Delta\theta=-\eta g$，相对更新尺度可写为：

$$
r_l=\frac{\lVert\Delta\theta_l\rVert_2}{\lVert\theta_l\rVert_2+\epsilon}
\approx\eta\frac{g_l}{\lVert\theta_l\rVert_2+\epsilon}
$$

梯度范数不是越大越好：长期接近零可能是断图或饱和，突然增大可能导致不稳定；还应结合损失、参数尺度和学习率判断。

## 最小手算

两层参数的梯度分别为 `[3,4]` 和 `[0,12]`。各层范数为 5 和 12，总范数为：

$$
\sqrt{5^2+12^2}=13
$$

若最大允许范数为 6.5，全局范数裁剪会把所有梯度乘以 $6.5/13=0.5$。它保留梯度方向，但把总长度减半。裁剪能限制一次异常更新，不能修复错标签和断开的计算图。

## 可执行 CPU 实验

实验先证明正确管道能够过拟合小批次，再故意在隐藏层使用 `detach()`，通过逐层梯度检查定位断图。

```python
import random
import numpy as np
import torch
from torch import nn

SEED = 42
random.seed(SEED)
np.random.seed(SEED)
torch.manual_seed(SEED)

x = torch.randn(16, 4)
y = ((x[:, 0] * x[:, 1] + 0.4 * x[:, 2]) > 0).long()

class TinyNet(nn.Module):
    def __init__(self, break_graph=False):
        super().__init__()
        self.hidden = nn.Linear(4, 16)
        self.output = nn.Linear(16, 2)
        self.break_graph = break_graph

    def forward(self, features):
        hidden = torch.relu(self.hidden(features))
        if self.break_graph:
            hidden = hidden.detach()  # 故意模拟错误
        return self.output(hidden)

def gradient_report(model):
    report = {}
    for name, parameter in model.named_parameters():
        report[name] = None if parameter.grad is None else parameter.grad.norm().item()
    return report

# 健康管道应能记住这个固定小批次。
model = TinyNet()
optimizer = torch.optim.Adam(model.parameters(), lr=0.05)
criterion = nn.CrossEntropyLoss()
initial_loss = criterion(model(x), y).item()
for _ in range(250):
    optimizer.zero_grad(set_to_none=True)
    loss = criterion(model(x), y)
    loss.backward()
    optimizer.step()
final_loss = criterion(model(x), y).item()
accuracy = (model(x).argmax(dim=1) == y).float().mean().item()

# 用钩子获取隐藏激活，并检查所有健康梯度。
activations = {}
handle = model.hidden.register_forward_hook(
    lambda module, inputs, output: activations.update(hidden=output.detach())
)
optimizer.zero_grad(set_to_none=True)
criterion(model(x), y).backward()
healthy_gradients = gradient_report(model)
handle.remove()

# 故意断开隐藏层，输出层仍有梯度，隐藏层梯度为 None。
broken = TinyNet(break_graph=True)
broken_loss = criterion(broken(x), y)
broken_loss.backward()
broken_gradients = gradient_report(broken)

assert final_loss < initial_loss * 0.05
assert accuracy == 1.0
assert torch.isfinite(activations["hidden"]).all()
assert all(value is not None and np.isfinite(value)
           for value in healthy_gradients.values())
assert broken_gradients["hidden.weight"] is None
assert broken_gradients["output.weight"] is not None
print(round(initial_loss, 4), round(final_loss, 4), accuracy)
print("broken gradients", broken_gradients)
```

## 实验结果解释

小批次达到 100% 训练准确率，只证明模型、损失、Autograd 和优化器在这 16 个样本上能够协作，不证明泛化。断图模型仍能产生正常 loss，输出层也仍有梯度；若只看总损失，很容易漏掉隐藏层完全学不到的问题。

## 训练与推理差异

诊断钩子、逐批梯度统计和异常检测适合短期定位，长期全部开启会拖慢训练或占用内存。推理阶段没有反向梯度，应监控输入漂移、输出分布、置信度和延迟；训练时还需记录学习率、梯度、激活与训练验证差距。

调用 `model.eval()` 后要用相同预处理复现异常。否则 Dropout、BatchNorm 或随机增强的变化会掩盖问题。

## 数据与验证风险

- “成功过拟合小批次”不能替代独立验证。
- 诊断批次必须人工检查，若其标签本身错误，测试结论没有意义。
- 训练好而验证差可能是过拟合，也可能是切分偏差或训练验证预处理不一致。
- 在测试集上反复排错会造成选择泄漏，应保留最终未触碰测试集。
- 全局均值可能掩盖少数类别故障，需要按类别、时间和业务切片检查[指标](../H-机器学习/06-指标.md)。

## 工程排错

| 现象 | 可能原因 | 优先检查 |
| --- | --- | --- |
| 小批次也无法过拟合 | 标签错位、断图、未更新 | 手工样本、逐层梯度、参数差值 |
| 初始损失远大于 `log(C)` | logits 尺度异常或标签问题 | 初始化、输入范围、类别编号 |
| 某层梯度为 `None` | `detach`、不可微路径、未参与前向 | 计算图、参数名、前向分支 |
| 梯度长期为零 | 激活饱和或死 ReLU | 激活直方图、初始化、归一化 |
| 损失突然 NaN | 非有限输入、溢出、学习率过大 | 首个异常批次、逐层有限性 |
| 训练好而验证差 | 过拟合、漂移或泄漏 | 学习曲线、拆分、预处理边界 |
| 训练越来越慢 | 图被意外保留或输入瓶颈 | `.detach()`、日志列表、数据加载 |

## 适用与不适用场景

这套顺序适合几乎所有监督式神经网络训练。强化学习、生成对抗训练和分布式异步训练还需要任务特有的回报、博弈稳定性或通信诊断。梯度统计只解释优化链路，不能单独判断业务数据是否代表未来流量。

## 学习收益

你应能从最低成本证据开始，把不收敛定位到数据、前向、损失、梯度或更新；能解释小批次过拟合的作用和边界；能用梯度、激活和参数变化验证假设。

## 给别人讲清楚

“先让模型背会一小页答案。如果一小页都背不会，就检查题目、答案和笔是否连通；背得会但考试差，才讨论泛化。”

## 自检问题

1. 为什么小批次过拟合成功不代表模型能上线？
2. loss 正常时，为什么某个早期层仍可能完全没有梯度？
3. 遇到 NaN 时，为什么应该保存并检查第一个异常批次？
