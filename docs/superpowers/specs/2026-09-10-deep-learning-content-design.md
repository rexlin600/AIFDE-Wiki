## 1. 建设目标

基于现有 `00-深度学习-MOC.md`，创建 16 篇可独立阅读、相互链接的深度学习主题笔记。内容以理解和交付一个可训练、可验证、可恢复的神经网络系统为目标，不写成孤立的模型架构百科。

读者完成本目录后，应能说明每个组件解决什么训练问题，跟踪张量形状和数据流，推导关键公式，用 NumPy 复刻核心计算，用 PyTorch 完成训练与验证，并通过损失、梯度、激活、显存和延迟定位故障。

## 2. 受众和讲解原则

受众可能只具备基础代数和 Python 知识。内容不预设读者能够直接阅读复杂公式，统一遵循以下顺序：

1. 先用真实 AI 任务说明为什么需要这个主题；
2. 再用自然语言、形状标注和小规模手算建立直觉；
3. 然后逐步引入公式，解释每个符号和关键推导步骤；
4. 用 NumPy 复刻机制，用 PyTorch 对照实际实现；
5. 最后讨论验证、性能、上线边界和工程排错。

公式不以数量衡量完整性。证明重点放在帮助读者理解模型行为的关键结论，例如链式法则如何产生梯度、初始化为何保持方差、缩放点积为何除以 $\sqrt{d_k}$、卷积输出尺寸和感受野如何得到。

## 3. 领域边界

本目录负责神经网络的表示学习、训练机制、经典架构和 PyTorch 工程。数学原理链接 `G-AI 基础`，但会在神经网络场景中重新解释公式的作用；数据拆分、泛化、指标和泄漏沿用 `H-机器学习`，不重复写成通用机器学习教程。

Transformer 在本目录讲结构、张量流、因果 Mask 和训练机制。LLM 预训练、指令微调、对齐、推理策略和应用接口属于 `J-大模型 LLM`。生产服务治理属于 `N-生产级 AI`。

## 4. 内容架构

采用训练系统主线，而不是按模型年代排列：

```text
任务与张量
→ 前向计算
→ 损失函数
→ 反向传播
→ 参数更新
→ 稳定训练
→ 验证与诊断
→ 保存与推理
→ 扩展到不同模型架构和训练规模
```

MOC 提供三个入口：

- 按训练系统学习，用于从零理解完整训练链路；
- 按模型架构学习，用于进入视觉、序列、Transformer、生成和图任务；
- 按故障现象学习，用于定位不收敛、过拟合、NaN、显存不足、检查点无法恢复和推理变慢。

## 6. 单篇结构

每篇可根据主题调整中间章节，但必须承担以下职责：

1. **它解决什么深度学习问题：** 从真实任务说明价值；
2. **不理解会造成什么错误：** 给出训练或部署失败；
3. **它在训练系统中的位置：** 说明输入、输出和上下游；
4. **从一个 AI 案例开始：** 明确任务、张量、标签、损失、指标和错误成本；
5. **先建立简单基线：** 说明复杂方法相对什么改进；
6. **张量形状与数据流：** 每一步标注轴的含义；
7. **核心机制：** 从直觉过渡到计算；
8. **公式推导或机制证明：** 定义符号，保留关键中间步骤；
9. **最小手算：** 用小张量得到可核对结果；
10. **NumPy 复刻：** 不依赖自动微分验证核心机制；
11. **PyTorch 实验：** 展示实际 API、训练或工程语义；
12. **实验结果解释：** 说明预期现象和不能推出的结论；
13. **训练与推理差异：** 覆盖模式、状态、随机性和性能；
14. **数据与验证风险：** 沿用机器学习目录的拆分与泄漏原则；
15. **工程排错：** 使用“现象、可能原因、优先检查”表格；
16. **适用与不适用场景：** 给出架构和技术选择边界；
17. **学习收益、讲解、自检、相关主题和资料来源。**

纯工程主题不强行为 NumPy 代码凑数，可以使用等价的状态、形状、内存或恢复实验，但必须可执行和可检查。

## 7. 主题案例与实验

| 主题 | 真实问题 | 核心实验 |
| --- | --- | --- |
| 多层感知机 MLP | 用非线性边界识别手写形状 | NumPy 两层前向与 PyTorch 小分类器 |
| 神经网络反向传播 | 让分类误差转化为各参数梯度 | 手算链式法则、有限差分与 Autograd 对照 |
| 神经网络参数初始化 | 让深层网络信号不过早爆炸或消失 | 比较错误初始化、Xavier 与 Kaiming 的激活和梯度方差 |
| 神经网络优化器 | 在噪声小批量上稳定降低损失 | 比较 SGD、Momentum 和 AdamW 的轨迹与收敛 |
| 神经网络正则化 | 小数据图像分类减少过拟合 | Weight Decay、Dropout、数据增强和早停消融 |
| 卷积神经网络 CNN | 检测图像中的局部缺陷 | 手算卷积、输出尺寸、感受野和 PyTorch 分类 |
| 循环神经网络 RNN 与 LSTM | 根据序列上下文判断类别 | 时间展开、梯度传播、门控记忆和 Padding |
| 注意力机制 | 从序列中动态聚合相关信息 | NumPy 缩放点积、Mask 和 PyTorch 等价性 |
| Transformer | 并行建立上下文表示 | 最小编码块、残差、归一化、前馈和因果 Mask |
| PyTorch 模型训练 | 构建可验证可恢复的训练循环 | Dataset、DataLoader、Module、训练验证与检查点 |
| 深度学习训练诊断 | 定位损失不降、过拟合和 NaN | 小批次过拟合、梯度与激活统计、消融 |
| 批处理与模型序列化 | 处理变长输入并可靠恢复推理 | Padding、Mask、动态批处理和 `state_dict` 往返 |
| 混合精度与分布式训练 | 扩大训练规模并控制数值风险 | CPU 语义实验、梯度缩放推导和多设备边界 |
| 生成模型 | 学习并采样数据分布 | 自编码器、GAN 和扩散目标的最小对照 |
| 图神经网络 | 利用关系结构完成节点任务 | 手算消息聚合与 PyTorch 张量实现 |
| 自定义算子与模型编译 | 扩展算子并优化执行性能 | 自定义 Autograd 梯度检查、编译与性能剖析 |

## 8. 统一符号和工程约定

- 批大小记为 $B$，序列长度记为 $T$，隐藏维度记为 $D$，注意力头数记为 $H$，类别数记为 $C$；
- 图像默认采用 PyTorch 的 `[B, C, H, W]`，序列默认采用 `[B, T, D]`；
- 所有随机实验固定 NumPy 和 PyTorch 种子；
- 默认在 CPU 可执行，不下载在线数据；
- 训练、验证和测试角色保持一致，测试集不参与调参；
- 训练循环显式展示 `zero_grad`、前向、损失、`backward` 和 `step`；
- 验证和推理使用 `model.eval()` 与 `torch.inference_mode()`；
- 检查点至少保存模型、优化器、步数和复现所需配置；
- CUDA、多卡和编译行为若无法在普通环境完整观察，要清楚标注硬件前提，不伪造实测结论。

- PyTorch API 以当前官方文档、教程和官方仓库为准；
- 模型机制优先引用原始论文或权威教材；
- 每篇记录机构或作者、标题、HTTPS 链接和访问日期 `2026-09-10`；
- 不复制第三方长文本或完整代码，实验使用原创小数据和最小实现；
- 涉及当前 API 的笔记填写 `last_verified: 2026-09-10`。

## 10. 验收标准

单篇完成需满足：

- Front Matter、文件名、标题、深度和重要程度与 MOC 一致；
- 开头可以直接看出真实 AI 用途和在训练链路中的位置；
- 关键张量形状能够从输入追踪到输出；
- 推导定义符号、不省略决定性步骤，并有可检查手算；
- NumPy 与 PyTorch 实验能在 CPU 隔离环境执行；
- 解释训练与推理差异、验证边界和工程排错顺序；
- 明确适用条件，不把更复杂架构默认视为更好；
- 权威来源直接支持核心机制和 API 行为。

整个目录完成需满足：

- 16 篇主题全部存在并由 MOC 直接链接；
- 训练系统、模型架构和故障现象三条路线均可独立导航；
- 张量符号、数据集角色和训练循环术语跨篇一致；
- 所有 Python 代码块实际执行，固定随机种子且无需在线下载；
- Markdown、Front Matter、标题、本地链接和排错表格检查通过；
- 任意打开一篇都能明确“为什么学、如何计算、怎样训练、如何验证、如何排错”。
