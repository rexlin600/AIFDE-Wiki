# 知识库中文命名设计

## 目标

将知识库编号目录 `00`–`15` 及其 Markdown 文件名改为中文优先的命名形式，同时保留必要的技术缩写，以提高导航的中文可读性。

## 范围

- 重命名 `00`–`15` 知识库目录及其下的 Markdown 文件。
- 更新这些知识库 Markdown 文件中指向被重命名笔记的 wikilink 路径，保持知识库内链接有效。
- 不修改 Markdown 正文和任何层级标题。
- 不修改根目录文档、`90-Templates` 或 `99-Assets`。
- 不修改现有 `.obsidian` 和 `.claudian` 的未提交变更。

## 命名约定

- 保留数字前缀以维持排序。
- 通用技术缩写保留英文；中文语义与英文缩写并列时，使用“中文 + 空格 + 英文/缩写”。
- MOC、ADR、EXP、RETRO、PRJ 等笔记类型前缀保留。
- 示例目录：
  - `00-Guide` → `00-用户指南`
  - `01-Roadmap` → `01-学习路线`
  - `02-AI-Foundations` → `02-AI 基础`
  - `05-LLM` → `05-大模型 LLM`
  - `06-RAG` → `06-检索增强生成 RAG`
  - `07-Agent` → `07-智能体 Agent`
  - `08-Multimodal-AI` → `08-多模态 AI`
  - `10-AI-Safety-Governance` → `10-AI 安全与治理`
  - `11-FDE-Practice` → `11-FDE 实践`

## 实施与验证

1. 生成完整的目录与文件旧名/新名映射，并检查目标路径是否重复。
2. 使用 Git 重命名目录和文件，保留变更历史可追踪性。
3. 仅在 `00`–`15` 的 Markdown 文件中，按映射更新 wikilink 目标路径；不改变链接显示文字或标题。
4. 运行 `python scripts/validate_wiki.py`，验证文件存在性、链接完整性及项目既有质量检查。
5. 检查 `git diff`，确保没有越过范围的文件变动。

## 风险与边界

根目录和模板目录不在修改范围内；若其中存在指向旧路径的链接，将按范围约束保持不变。因此验证结果会明确报告此类引用，而不会擅自修改这些文件。
