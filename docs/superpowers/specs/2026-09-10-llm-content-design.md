# 大模型 LLM 内容补全设计

<!-- markdownlint-disable MD013 -->

**日期：** 2026-09-10

**状态：** 已按用户授权确认并进入实施

**范围：** `J-大模型 LLM`

## 1. 建设目标

基于现有 MOC 创建和完善 20 篇独立主题笔记，使读者能够从文本进入模型开始，理解预训练、生成、适配、应用接口、评测、推理成本和模型选择，并能把知识用于真实 LLM 系统。

内容不写成名词解释集合。每篇都回答为什么需要该技术、它改变了 LLM 链路的哪一部分、怎样计算或验证、容易在哪里失败，以及何时应改用 Prompt、RAG、工具、微调或更换模型。

## 2. 受众和讲解方式

受众可能不了解概率、矩阵或深度学习细节。每篇按照以下层次展开：

1. 真实问题和失败案例；
2. 不使用复杂方法时的简单基线；
3. 输入输出、Token 流和系统位置；
4. 低门槛直觉；
5. 符号定义、关键公式推导和最小手算；
6. 可执行的 NumPy、PyTorch 或纯 Python 实验；
7. 评测、成本、延迟、安全和排错；
8. 适用边界、讲解话术和自检问题。

机制主题强调公式和张量；应用接口主题强调状态机、Schema 和失败恢复；服务主题强调延迟、吞吐和成本计算。不会为了形式统一而加入无意义数学。

## 3. 领域边界

- Transformer 通用结构链接 `I-深度学习`，本目录只补自回归生成和 LLM 特有推理路径。
- 通用数据拆分、指标和泄漏链接 `H-机器学习`。
- 文档摄取、检索、重排和引用属于 `K-检索增强生成 RAG`。
- 多步工具循环、记忆和可靠执行属于 `L-智能体 Agent`。
- 平台级网关、Tracing、容量和发布治理属于 `N-生产级 AI`。

## 4. 组织主线

```text
文本与 Token
→ Embedding 与位置
→ 预训练目标
→ 自回归 Transformer
→ 采样与 KV Cache
→ Prompt 与上下文
→ 结构化输出与工具调用
→ 幻觉与评测
→ SFT、LoRA、偏好优化与蒸馏
→ 量化、服务和模型选型
→ 从头训练与长上下文扩展
```

MOC 同时提供生命周期、问题决策和故障现象三个入口。

## 6. 统一单篇职责

每篇至少包含：

- 它解决什么 LLM 问题；
- 不理解会造成什么错误；
- 它在 LLM 链路中的位置；
- 一个明确的真实应用案例；
- 最简单可用基线；
- 输入输出或状态流；
- 核心机制与关键公式推导；
- 最小手算；
- 可执行实验与结果解释；
- 质量、延迟和成本影响；
- 数据、评测与安全风险；
- 工程排错表；
- 适用与不适用场景；
- 学习收益、讲解、自检、相关主题和权威来源。

每篇至少一个无需网络下载的可执行 Python 实验。机制主题优先使用 NumPy 或 PyTorch；接口主题使用标准库模拟 Schema、重试、状态和失败分支。实验固定随机种子，禁止依赖付费 API 或远程模型。

## 7. 主题验证重点

| 主题组 | 必须验证的现象 |
| --- | --- |
| Tokenizer 与 Embedding | 词表合并、序列长度、查表、池化和相似度边界 |
| 预训练与自回归 Transformer | 标签移位、因果不可见性、交叉熵和困惑度 |
| Prompt 与 Context | 版本化、预算、截断顺序、指令冲突和上下文污染 |
| 结构化输出与工具调用 | Schema 校验、参数验证、权限边界、超时、重试和回填 |
| 幻觉与模型选型 | 错误分类、可证伪评测、拒答、质量成本延迟的统一决策 |
| SFT、LoRA、RLHF/DPO、蒸馏 | 数据格式、目标函数、可训练参数、偏好对和基线污染 |
| 采样与 KV Cache | 温度、top-k、top-p、停止条件、缓存等价性和显存估算 |
| 量化与服务 | 误差、校准数据、首 Token 延迟、逐 Token 延迟、吞吐和并发 |
| 从头预训练与长上下文 | 数据治理、规模预算、检查点、MoE 路由和长度外推 |

## 8. 来源与 API

- 机制优先引用原始论文、Hugging Face 官方文档与 PyTorch 官方文档。
- OpenAI 产品行为仅在必要时引用 OpenAI 官方文档，避免把供应商特性写成通用标准。
- 当前 API 和库行为记录核验日期 `2026-09-10`。
- 不复制第三方长文本、模型输出或大段代码。

## 9. 验收标准

- 20 篇主题全部存在并由 MOC 直接链接；
- 任意打开一篇都能看出真实 LLM 用途，而不是脱离应用的数学说明；
- 关键公式有符号定义、推导步骤和可核对手算；
- 每篇至少一个代码块，全部在隔离环境执行；
- 所有主题都明确评测方法、成本或延迟影响和安全边界；
- MOC 的三条导航路线能够独立使用；
- Markdown、Front Matter、一级标题、本地链接和排错表检查通过；
- 与深度学习、RAG、Agent 和生产 AI 的内容边界清楚。
