# 机器学习内容补全设计

**日期：** 2026-09-09

**状态：** 已确认，可进入实施计划阶段

**范围：** `H-机器学习`

## 1. 建设目标

基于现有 `00-机器学习-MOC.md`，创建 15 篇可独立阅读且相互链接的机器学习主题笔记。内容以建立、验证和交付可泛化预测系统为目标，不写成孤立的算法百科。

每篇从具体预测或决策问题出发，贯穿业务目标、样本单位、标签、预测时点、数据拆分、特征、基线、模型、指标、阈值、错误分析和工程排错。读者应理解为什么使用某种方法、不使用会犯什么错误，以及如何用证据判断模型是否值得上线。

## 2. 领域边界

机器学习目录负责讲解如何把数据和算法用于实际建模、验证和决策。数学原理继续由 `G-AI 基础` 负责；遇到校准、PCA、似然、优化和因果等重叠内容时，本目录只做应用所需回顾并链接权威基础笔记，不重复大段推导。

神经网络内部机制、深度学习训练和 LLM 应用分别由相邻领域负责。本目录重点提供传统模型基线、数据与评测方法，以及判断是否确实需要更复杂模型的证据。

## 3. 统一机器学习工作流

```text
业务目标与错误成本
→ 定义样本单位、标签和预测时点
→ 拆分训练验证测试集
→ 特征工程和 Pipeline
→ 建立朴素基线
→ 训练候选模型
→ 选择指标和阈值
→ 错误分析与校准
→ 上线监控漂移
→ 决定重训、降级或人工处理
```

MOC 同时提供两个入口：

- 按建模工作流进入，用于从工程阶段或故障定位主题；
- 按任务类型进入，用于区分监督学习、无监督学习、排序、时序与因果问题。

## 5. 单篇结构

每篇根据主题适当调整小节，但必须承担以下职责：

1. **它解决什么机器学习问题：** 明确预测或决策问题和价值。
2. **不理解会造成什么错误：** 给出模型、数据或决策层面的失败。
3. **它在建模工作流中的位置：** 说明上下游输入输出。
4. **从一个业务案例开始：** 明确预测对象、输入特征、目标变量、预测时点和错误成本。
5. **先建立简单基线：** 说明复杂方法相对什么改进。
6. **核心机制：** 以低门槛语言解释模型或方法如何工作。
7. **训练过程和关键参数：** 解释参数影响与调试依据。
8. **最小手算：** 用少量数据完成可检查计算。
9. **可执行实验：** 使用 NumPy 或 scikit-learn，固定随机种子和拆分。
10. **评测与结果解释：** 使用匹配任务和错误成本的指标。
11. **数据与泄漏风险：** 明确预测时点、拆分单位和预处理边界。
12. **工程排错：** 使用“现象 → 可能原因 → 优先检查”表格。
13. **适用与不适用场景：** 给出模型选择边界。
14. **学习收益：** 明确读者能够解释、实现和排查什么。
15. **讲解、自检、相关概念和资料来源。**

数学基础较弱的读者可以先沿案例、直觉、实验和排错主线学习；必要公式逐步引入，并链接 AI 基础中的完整原理。

## 6. 主题案例与实验

| 主题 | 核心问题 | 基线与实验重点 |
| --- | --- | --- |
| 回归 | 预测订单交付时长 | 均值基线、线性回归、Ridge、MAE、RMSE 和残差 |
| 分类 | 预测客户是否流失 | 多数类基线、逻辑回归、概率、阈值和类别不平衡 |
| 树与 Boosting | 建立强表格数据基线 | 决策树、随机森林、梯度提升、过拟合和特征重要性 |
| 特征工程 | 把原始业务字段变成稳定输入 | 缺失值、类别编码、缩放、Pipeline 和训练服务一致性 |
| 数据泄漏 | 防止模型偷看预测时点之后的信息 | 目标泄漏、时间泄漏、重复用户和预处理泄漏 |
| 指标 | 把模型错误映射成业务成本 | 混淆矩阵、Precision、Recall、F1、PR-AUC 和阈值 |
| 聚类 | 在无标签数据中发现用户群体 | K-Means、缩放、轮廓系数、簇稳定性和业务解释 |
| 降维 | 压缩高维特征并保留有效信息 | PCA、解释方差、可视化与下游任务指标 |
| 异常检测 | 发现罕见交易或系统行为 | 统计规则、Isolation Forest、污染率和无标签评测 |
| 校准 | 让模型概率对应真实发生频率 | 可靠性曲线、Brier Score、Platt 和 Isotonic |
| 验证设计 | 让离线结果代表真实部署方式 | 留出、交叉验证、GroupKFold、TimeSeriesSplit 和嵌套验证 |
| 推荐系统 | 为用户排序可能感兴趣的内容 | 热门基线、内容推荐、协同过滤、Recall@K 和冷启动 |
| 时间序列 | 预测未来需求 | 朴素季节基线、滞后特征、滚动回测和时间泄漏 |
| 在线学习 | 数据持续到达时增量更新模型 | `partial_fit`、概念漂移、延迟标签和在线评测 |
| 因果机器学习 | 估计优惠券对不同用户的增量效果 | 倾向得分、加权估计、T-Learner、共同支持和策略评测 |

## 7. 内容规则

- 每篇开头先说明业务和机器学习问题，不从算法定义开始。
- 每个案例明确“对谁、在什么时候、预测或决定什么”。
- 每篇至少有一个朴素基线，说明复杂模型改善了什么。
- 每篇至少包含一个可执行实验，并解释输入、拆分、输出和预期现象。
- 监督学习不得在训练集上报告最终效果。
- 无监督学习不得只凭可视化好看来宣称有效。
- 推荐、时间序列和因果任务不得套用普通随机分类拆分。
- 每篇明确数据泄漏入口、验证方式、适用指标和错误成本。
- 模型选择必须给出不适用条件，不把更复杂的方法默认视为更好。
- 工程建议与数学事实分开表述，经验判断说明适用条件。

## 8. 来源要求

- 优先使用论文、教材、标准、scikit-learn 官方文档和官方仓库。
- 每篇至少包含直接支持核心方法和 API 行为的权威来源。
- 来源记录作者或机构、标题、HTTPS 链接和访问日期 `2026-09-09`。
- 涉及当前 API 的内容填写 `last_verified: 2026-09-09`。
- 不复制第三方长文本或代码，示例使用原创小规模数据和实现。

## 9. 验收标准

单篇完成需满足：

- Front Matter、主题名、深度和重要程度与 MOC 一致；
- 前几节即可看出解决什么业务和机器学习问题；
- 明确样本单位、标签或输出、预测时点和错误成本；
- 有朴素基线、可执行实验、验证方式和结果解释；
- 明确数据泄漏、适用边界和工程排错顺序；
- 与 AI 基础的重叠知识使用链接，不复制大段推导；
- 权威来源能够直接支持核心结论；
- Markdown、Front Matter、本地链接和代码块检查通过。

整个目录完成需满足：

- 15 篇主题全部存在并由 MOC 直接链接；
- MOC 的建模工作流和任务类型两条路线均可独立导航；
- 术语、数据集角色、指标和预测时点跨篇一致；
- 实验固定随机种子，不使用测试集调参；
- 排序、时间序列、在线学习和因果任务使用各自正确的验证方式；
- 任意打开一篇都能明确“为什么学、如何用、怎样验证和如何排错”。
