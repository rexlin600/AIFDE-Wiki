# RAG 主题笔记设计

**日期：** 2026-09-10

## 目标

将 `K-检索增强生成 RAG` 建设为一套面向数学与工程基础不一读者的完整知识体系。读者不仅知道各种 RAG 技术是什么，还应理解它们解决哪个 AI 应用问题、处在数据到回答链路的哪个位置、为什么有效、怎样验证、何时不该使用，以及质量、延迟、成本、权限和安全之间的取舍。

## 受众与写作原则

- 面向第一次系统学习 RAG 的开发者，也能支持有经验的工程师复查公式、指标与边界。
- 每篇是可独立阅读的主题笔记，标题直接表达主题，不使用顿号等并列符号。
- 先从真实 AI 应用和失败现象切入，再逐层进入状态、公式与实现。
- 数学符号首次出现时解释含义；公式配手算，不跳过关键推导。
- 每篇至少包含一个无需网络、付费 API 或模型下载的 Python 实验。
- 实验只证明正文明确限定的结论，不用模拟数据冒充真实业务结果。
- 统一说明数据版本、评测污染、权限、删除传播、成本和可观测性。

## 方案选择

采用完整主题拆分方案。每种主要机制独立成篇，MOC 提供生命周期、故障现象和方案决策三种入口。

未采用以下方案：

- 十余篇综合长文：文件更少，但查询改写、路由、纠错和高级图检索难以独立定位。
- 只扩写当前 MOC 十个大类：导航简洁，但不能达到逐主题分层讲透的目标。

## 知识架构

主线按一次 RAG 请求的生命周期组织：

```text
数据进入
  → 解析清洗
  → 切分与元数据
  → 稀疏和向量索引
  → 查询理解
  → 候选召回
  → 融合与重排序
  → 上下文构建
  → 带引用生成
  → 检索和回答评测
  → 权限时效与持续更新
```

高级 RAG 方法只有在静态单轮基线暴露出明确错误后引入。每篇必须说明自己改变生命周期中的哪个环节，以及新增的状态、延迟和失败模式。

## 单篇统一结构

每篇主题笔记至少承担以下职责，章节可以按主题自然命名，但不能遗漏：

1. 它解决什么 RAG 问题。
2. 不理解会造成什么错误。
3. 它在 RAG 链路中的位置。
4. 一个真实 AI 应用案例和不用该方法的简单基线。
5. 输入、输出、索引或状态的形状与数据流。
6. 机制、公式或状态转移的逐步推导。
7. 可人工复核的最小手算。
8. 可离线执行的 Python 实验和断言。
9. 实验能证明什么、不能证明什么。
10. 检索质量、生成质量、延迟与成本影响。
11. 数据、评测、权限、时效和安全风险。
12. 固定表头的工程排错表。
13. 适用和不适用场景。
14. 学习收益、复述检查与自检问题。
15. 相关主题和权威资料来源。

固定排错表头为：

```markdown
| 现象 | 可能原因 | 优先检查 |
| --- | --- | --- |
```

## 公式和实验要求

- BM25 推导词频饱和、IDF 和长度归一化，并与简单关键词基线对照。
- Dense Retrieval 推导余弦或点积、对比损失和困难负例影响。
- Hybrid 实现 RRF，不直接混加未校准的异构分数。
- 向量索引用小规模精确搜索和近似候选模拟解释 Recall 与查询量。
- 重排序区分召回上限和精排顺序，候选中没有相关文档时不得声称能修复。
- 查询类主题必须有意图保持、去重、预算和失败分支断言。
- 多跳、迭代、纠错和 Agentic RAG 必须显式设置状态、最大步数与终止原因。
- 图和层级主题使用小型内存图或树，不依赖外部数据库。
- 权限、多租户、时效和更新实验必须包含越权、旧版本或重复事件的失败断言。
- 检索评测手算 Recall@k、MRR 和 nDCG；生成评测区分答案正确、证据支持和引用归属。
- 随机实验固定种子；全部代码块独立执行，不共享前一篇状态。

## 边界

- LLM 的 Token、Embedding、上下文窗口、结构化输出和幻觉只建立前置链接，不重复完整原理。
- Agent 目录负责通用规划、记忆和工具编排；本目录只讲以检索为目标的受控循环。
- 多模态目录负责视觉与音频模型本身；本目录只讲多模态材料如何被索引、召回和作为证据。
- 生产级 AI 目录负责通用平台、监控与发布；本目录聚焦 RAG 特有的索引版本、权限过滤、引用和更新一致性。
- 安全治理目录负责全面威胁模型；本目录必须覆盖检索边界内的越权、提示注入、数据泄露和删除传播。

## MOC 设计

MOC 提供四种入口：

- 生命周期导航：数据、索引、查询、检索、上下文、生成、评测、运行。
- 故障导航：召回为空、排序错误、引用不符、答案无依据、越权、知识过期、延迟和成本异常。
- 方法决策：Sparse、Dense、Hybrid、Rerank、高级 RAG、GraphRAG、长上下文、工具和微调。
- 学习层次：核心、常用和拓展主题。

MOC 必须直接链接全部 38 篇主题笔记，并保留检索基线实验入口。

## 验收标准

- 目录包含 38 篇主题笔记、1 篇检索基线实验和 1 个 MOC。
- 所有主题的文件名与一级标题一致表达单一主题，一级标题不含顿号、中文括号等装饰符号。
- Front Matter 与清单中的深度和重要程度一致，日期核验为 `2026-09-10`。
- 每篇包含 AI 应用价值、离线 Python 实验、固定排错表、自检与权威来源。
- MOC 直接覆盖全部主题，所有本地 Markdown 链接可解析。
- 所有 Python 代码块在隔离环境逐块执行成功。
- `markdownlint-cli2` 和 `git diff --check` 无错误。
- 最终由主代理交叉审查公式、手算、实验结论、绝对化表述和领域边界。

## 分批实施

1. 数据与基础检索：数据摄取、解析、清洗、切分、元数据、BM25、Dense、Hybrid、向量索引与重排序。
2. 查询与上下文：父子文档、查询改写、多查询、分解、路由、HyDE、多轮、多跳和上下文构建。
3. 高级 RAG：自适应、迭代、纠错、Self-RAG、Agentic RAG、GraphRAG、知识图谱、层级与 RAPTOR。
4. 数据形态与生产治理：结构化、多模态、权限、多租户、时效、流式更新和引用。
5. 评测与决策：检索评测、生成评测、方案选型、MOC 和全目录验收。
