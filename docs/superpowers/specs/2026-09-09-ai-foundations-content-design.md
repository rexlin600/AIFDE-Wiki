# AI 基础内容补全设计

**日期：** 2026-09-09

**状态：** 已确认，可进入实施计划阶段

**范围：** `G-AI 基础`

## 1. 建设目标

基于现有 `00-AI 基础-MOC.md`，为数学与 AI 基础领域建立一组可独立阅读、相互链接的权威概念笔记。内容面向数学基础可能不完整的 AI 工程学习者，既要容易理解，也要保留关键结论的完整推导，使读者最终能够用自然语言、数字示例、公式和 AI 工程案例向他人讲清楚主题。

本次补全不扩展机器学习算法、深度学习架构或 LLM 应用工程；这些内容继续由相邻领域负责。MOC 负责领域边界、学习顺序和导航，概念笔记负责解释正文。

## 2. 目标读者与前置条件

目标读者具备高中代数和基础 Python 能力，但不假定已经系统掌握线性代数、概率论、高等数学或优化理论。

读者应能：

- 理解变量、函数、指数和对数的基本含义；
- 阅读简单 Python，并使用 NumPy 操作数组；
- 区分样本、特征、参数、预测和指标。

缺失的高等数学知识由正文按需补充。文档不得使用“显然”“易得”等表达跳过对初学者关键的推理步骤。

## 4. 单篇内容结构

每篇概念笔记遵循相同的学习路径，但可以根据主题删减不适用的小节：

1. **一句话定义：** 用普通语言准确界定主题。
2. **本篇范围：** 明确覆盖内容、排除内容及相邻领域边界。
3. **前置知识：** 链接必要的前序主题，并按需提供最小补充。
4. **为什么重要：** 从真实 AI 问题说明学习动机。
5. **直觉理解：** 使用具体数字、图形、类比或工程场景建立心智模型。
6. **核心概念：** 逐个定义术语、符号、类型、形状和单位。
7. **工作原理：** 解释输入、输出、过程、依赖条件和边界情况。
8. **推导与证明：** 不跳步地展开核心结论，并说明每一步使用的规则。
9. **手算示例：** 先用具体数字完成可检查的最小计算。
10. **NumPy 实验：** 验证公式、形状、误差或边界行为，并解释预期结果。
11. **AI 工程实践：** 连接模型、损失、训练、评测、数值计算或不确定性判断。
12. **公式看不懂时：** 用自然语言重新表达关键公式的输入、动作和结果。
13. **适用与不适用场景：** 给出判断依据，而非只列场景名称。
14. **常见误区：** 解释错误直觉的来源、错误所在和纠正方法。
15. **如何给别人讲清楚：** 提供一份 3～5 分钟讲解顺序。
16. **自检问题：** 同时覆盖自然语言解释、数字计算、公式推导和工程判断。
17. **相关概念：** 连接前置、后续、相似和容易混淆的主题。
18. **资料来源：** 记录直接支持正文结论的权威资料和访问日期。

结构服务于理解，不机械保留空标题。例如，因果推断重点组织假设、因果图和识别过程；数值稳定性重点组织失败样例、稳定变换和误差实验。

## 5. 低门槛表达规则

每个概念按照“具体问题 → 数字示例 → 自然语言规则 → 数学定义 → 一般推导 → 工程应用”的顺序展开。

- 一个段落原则上只引入一个新概念。
- 每个符号首次出现时说明含义、取值范围、类型，以及适用时的形状或单位。
- 先用标量和小规模数字手算，再推广到向量、矩阵或一般形式。
- 公式纵向分步书写；每一步解释变换依据和目的。
- 关键推导同时包含主线解释和严格条件。主线保证初学者不断线，严格部分保证结论可核查。
- 类比只帮助建立直觉，不代替定义；正文要明确类比在哪些情况下失效。
- 代码示例解释输入、输出、数组形状、预期结果和失败行为，不只展示代码。
- 图表只有在明显降低理解难度时使用，核心结论仍须能从 Markdown 正文独立理解。
- 每篇结束时，读者应能不用公式解释主题、用简单数字完成计算，并说明其在 AI 系统中的作用。

## 6. 各主题的讲透边界

| 主题 | 核心问题 | 重点推导或证明 | 最小实验 |
| --- | --- | --- | --- |
| 线性代数 | 数据和参数如何表示及变换 | 内积、矩阵乘法、范数、余弦相似度和形状规则 | 批量矩阵计算和相似度 |
| 概率统计 | 如何描述随机性并由样本理解总体 | 条件概率、贝叶斯公式、期望、方差、协方差和置信区间 | 抽样分布与区间覆盖率 |
| 微积分与梯度 | 输出如何随输入变化 | 导数规则、偏导数、方向导数、梯度和链式法则 | 解析梯度与有限差分 |
| 优化 | 如何寻找使目标函数更小的参数 | 从局部近似推导梯度下降，并比较批量和随机优化 | 学习率与收敛轨迹 |
| 数值稳定性 | 正确公式为什么可能算出错误结果 | 浮点误差、溢出、下溢、稳定 Softmax 和 LogSumExp | 极端输入下的稳定计算 |
| 信息论 | 如何度量信息和分布差异 | 信息量、熵、交叉熵、KL 散度和 KL 非负性 | 分类交叉熵与分布比较 |
| 矩阵分解 | 如何提取矩阵的主要方向和低秩结构 | 特征分解、奇异值分解和低秩近似 | 图像或数据矩阵压缩 |
| 最大似然与最大后验 | 如何从概率模型得到参数和损失 | 伯努利与高斯似然、对数似然、MAP 和正则化关系 | 参数估计与正则化对比 |
| 自动微分直觉 | 框架如何准确高效地计算导数 | 计算图、局部导数、前向模式和反向模式 | 手算小图与框架结果对照 |
| 凸优化 | 何时局部解可以成为全局解 | 凸集、凸函数、一阶和二阶条件、约束与对偶直觉 | 凸函数与非凸函数轨迹对比 |
| 不确定性量化 | 如何判断预测有多可信 | 预测区间、后验、校准和分布外不确定性 | 覆盖率与校准曲线 |
| 因果推断 | 如何区分相关、干预和因果 | 混杂、反事实、因果图和后门调整直觉 | 混杂数据与干预结果对比 |
| 信息几何 | 如何用几何理解概率分布空间 | Fisher 信息和 KL 散度的局部几何关系 | 简单分布族的距离近似 |

完整推导只要求覆盖每篇的核心结论。扩展定理需要说明结论、成立条件、用途和证明入口，但不为追求形式完整而引入整套数学专业课程。

## 7. MOC 与跨文档关系

`00-AI 基础-MOC.md` 保留现有领域边界、推荐顺序和主题分类，并将主题名称改为对应概念笔记的相对 Markdown 链接。

- 每个概念只保留一篇权威笔记。
- 前置关系使用相对 Markdown 链接表达。
- 重复使用的基础结论链接回首次完整讲解的位置，不在多篇文档中复制整段推导。
- 与机器学习、深度学习和 LLM 的关系只解释到足以说明用途的程度，具体算法和架构链接到相邻领域。
- GitHub Markdown 是最低阅读基线，不依赖 Obsidian 专属语法完成关键导航。

## 8. 来源与事实要求

- 优先使用教材、原始论文、标准、官方课程、官方文档和官方仓库。
- 每篇至少包含能够直接支持核心定义和推导的资料来源。
- 来源条目记录标题、作者或发布机构、HTTPS 链接及访问日期。
- 数学事实与工程建议分开表述；经验判断不得伪装成数学定理。
- 易变的框架行为须核对当前官方文档，并填写 `last_verified`。
- 不大段复制来源内容，所有解释以原创中文表述为主。

## 9. 验收标准

单篇笔记达到以下条件才算完成初稿：

- Front Matter 合法，主题、深度和重要程度与 MOC 一致；
- 主题边界明确，没有越界复制相邻领域内容；
- 核心术语和符号均在首次出现时解释；
- 至少包含一个完整核心推导或证明、一个手算例子和一个 NumPy 实验；
- 代码可以运行，文中数值结果与实际输出一致；
- 至少解释一个 AI 工程应用和两个常见误区；
- 包含 3～5 分钟讲解提纲和分层自检问题；
- 权威来源能直接支持核心结论；
- MOC、前置主题和相关概念链接有效；
- 仓库测试、Wiki 校验和 Markdown lint 全部通过。

整个目录完成时，还需检查 13 篇笔记的术语、符号、链接和内容边界是否一致，并确认 MOC 的推荐顺序能够从低门槛基础逐步进入拓展主题。

## 10. 实施原则

实施按依赖顺序分批进行：先完成线性代数、概率统计、微积分与梯度，再完成优化和数值稳定性；随后完成信息论、矩阵分解、参数估计和自动微分；最后完成四个拓展主题。每批完成后执行内容复核和自动检查，避免 13 篇全部写完后才发现统一结构或符号体系存在问题。
