# 如何评测一个 RAG 系统

## 问题

给定一个用于企业知识问答的检索增强生成（Retrieval-Augmented Generation，RAG）系统，如何判断它能否上线？请说明数据集、离线与在线方法、检索/生成/引用/业务指标、LLM-as-Judge 风险，以及如何定位失败。

## 考察能力

这道题考察能否把“回答看起来不错”拆成可归因的系统质量，建立从离线回归到线上业务结果的证据链，并处理权限、分布变化、人工评审成本和指标冲突。

## 回答结构

1. 澄清用户、任务、知识时效、风险等级、流量和上线决策。
2. 定义业务主指标与不能退化的安全、成本、延迟护栏。
3. 构建带分群、难例、权限和不可回答样例的版本化数据集。
4. 分别评测检索、生成、引用与端到端任务，建立失败归因。
5. 先离线比较与回归，再灰度上线，用实验和人工抽检监控长期表现。

## 参考答案

### 数据集构建

从真实且获准使用的查询分布抽样，保留查询、时间点、用户权限、期望证据、可接受答案要点和“应拒答/应澄清”标签。按业务场景、语言、长尾、时间敏感、冲突资料、表格/图片、越权诱导和无答案分群；训练、调参和最终测试集隔离。标签由领域专家制定指南后双人复核，记录分歧。每次知识库或索引变化都给数据集与语料快照版本，避免用未来资料回答历史问题。

### 四层指标

| 层级 | 关键问题 | 可选指标与检查 |
| --- | --- | --- |
| 检索 | 所需证据是否被取回并排在可用位置？ | Recall@k、MRR、nDCG、命中文档/片段覆盖、权限过滤正确率、空检索率、检索延迟 |
| 生成 | 答案是否正确、完整、相关且遵守指令？ | 要点覆盖、事实一致性、拒答/澄清正确率、格式合规、毒性与隐私泄露率 |
| 引用 | 每个可核验主张能否由所引证据支持？ | Citation precision/recall、主张—证据蕴含、链接有效性、引用位置与来源权限 |
| 端到端业务 | 系统是否改善真实任务且风险可接受？ | 任务成功率、一次解决率、处理时长、人工升级率、采纳/修订率、严重错误率、延迟和单任务成本 |

指标必须配基线与置信区间。基线可包括关键词检索、无 RAG 的模型、当前人工流程或生产旧版本；不同风险分群分别报告，不能让大量简单问题掩盖少量高危失败。

### 离线评测

固定语料、索引、模型、Prompt 和随机设置，对候选系统跑同一测试集。先检查检索上限：若 gold evidence 不在 top-k，生成器无法补救；再做 oracle-context 实验，把正确证据直接给生成器，区分检索失败与生成失败。对每个失败标注摄取、切分、索引、查询改写、召回、重排、上下文拼装、生成、引用或权限原因。重要变更设置回归门槛，同时人工查看严重错误和代表性样例。

### 在线评测

通过 Shadow、Canary 或 A/B 测试逐步放量，预先定义主指标、护栏、样本量/周期和停止条件。记录端到端 Trace，但对敏感内容脱敏并执行最小权限与保留策略。结合显式反馈、用户修订、任务完成、人工升级和延迟/成本；反馈按钮不能单独代表正确性。监控查询与语料分布漂移，定期抽样给领域专家复核，并把已确认失败加入回归集。

### LLM-as-Judge 风险

LLM Judge 可降低大规模评审成本，但可能偏好冗长或特定措辞、自洽地接受错误、受被评文本 Prompt Injection 影响，并随模型或版本变化产生漂移。控制方法包括明确 rubric 和离散评分、隐藏系统身份、随机交换候选顺序、多个 Judge/多次采样、保留理由、用人工金标做校准，以及把高风险与低一致性样例升级给专家。Judge 分数是测量工具，不是未经校准的事实标签。

### 上线判断

只有当业务主指标相对基线达到预设门槛、关键分群没有不可接受退化、安全/权限护栏通过、延迟和成本在预算内，并且监控、人工兜底、回滚与责任人就绪时才 Go。平均质量上升但高危引用错误增加时应 No-Go 或限制场景。

## 常见错误

- 只用一个“答案正确率”混合所有失败，无法定位改进点。
- 只评生成文本，不检查检索证据、引用支撑和权限过滤。
- 用测试集反复调参，或没有固定语料、模型和 Prompt 版本。
- 把 LLM Judge 当金标，不校准偏差和跨版本漂移。
- 把点赞率当业务成功，忽略采样偏差、任务完成与严重错误。
- 只报均值，不看高风险分群、置信区间和最坏失败。

## 追问

- 没有完整 gold context 时，如何建立低成本检索标签？
- Recall@k 上升但端到端质量下降，可能有哪些原因？
- 如何评测多跳问题、冲突资料和“正确答案是拒答”的问题？
- 如何避免离线测试集泄漏到 Prompt、示例或语料？
- 医疗或法律场景中，哪些指标应成为硬门禁而非加权平均项？
- 上线后模型提供商更新版本，如何判断是否需要重新评测？

## 项目证据

一份有说服力的证据包应包含：数据集卡与版本、标注指南和一致性、候选配置、可重复运行命令、四层指标及置信区间、错误分类与代表样例、成本/延迟、上线门禁、线上实验方案、仪表盘或 Trace、回滚记录，以及由失败进入回归集的闭环。可以关联[项目档案](../Q-%E9%A1%B9%E7%9B%AE/00-%E9%A1%B9%E7%9B%AE-MOC.md)，但不得虚构评测结果。
