# 阶段 3：RAG 工程

## 建议周期与进入条件

**建议周期：8～12 周，每周 5～10 小时。** 时间是建议；数据清理和评测集构建通常比拼接框架更耗时。

进入条件是能稳定调用 LLM、生成并比较 Embedding、校验结构化输出、构建固定评测集，并能记录质量、延迟和成本。

## 推荐深度与核心知识

RAG 主链路达到 L3，高级 RAG 至少达到 L2：

领域入口：[RAG](../K-%E6%A3%80%E7%B4%A2%E5%A2%9E%E5%BC%BA%E7%94%9F%E6%88%90%20RAG/00-%E6%A3%80%E7%B4%A2%E5%A2%9E%E5%BC%BA%E7%94%9F%E6%88%90%20RAG-MOC.md)，并按需进入[生产 AI](../N-%E7%94%9F%E4%BA%A7%E7%BA%A7%20AI/00-%E7%94%9F%E4%BA%A7%E7%BA%A7%20AI-MOC.md)与[安全治理](../O-AI%20%E5%AE%89%E5%85%A8%E4%B8%8E%E6%B2%BB%E7%90%86/00-AI%20%E5%AE%89%E5%85%A8%E4%B8%8E%E6%B2%BB%E7%90%86-MOC.md)补齐运行和权限边界。

- 文档解析、清洗、切分、元数据、增量摄取和版本/删除传播。
- Sparse、Dense、Hybrid Retrieval，Metadata Filtering 与访问控制。
- Top-k、Reranker、Context Packing、Grounding 和可核验引用。
- Query Rewrite、Multi-Query、Decomposition、Routing 与 Parent-Child。
- GraphRAG、Agentic RAG、Self/Corrective RAG 等高级方法的适用前提。
- 检索指标、生成指标、引用正确性、端到端任务成功率和错误分类。
- 缓存、并发、索引更新、延迟分解、成本预算和数据安全。

## 必做实验

以同一公开语料、同一问题集和同一生成模型构建 `production-rag-system`，至少比较：

1. **Naive：** 固定切分、Dense Retrieval、Top-k 拼接。
2. **Hybrid：** 融合 Sparse 与 Dense Retrieval。
3. **Rerank：** 对召回候选进行重排序后再构造上下文。
4. **高级 RAG：** GraphRAG、Agentic RAG、Query Decomposition 或其他一种有明确假设的方法。

评测集必须包含可回答、不可回答、精确实体/编号、跨文档综合、时效和权限边界样例。每种方案报告 Recall@k 或 nDCG、答案正确性、Faithfulness、引用正确性、拒答、p50/p95 延迟和单请求成本。

## 外部 GitHub 项目

- [LlamaIndex](https://github.com/run-llama/llama_index)：研究摄取、索引、检索器与响应合成边界。
- [RAGFlow](https://github.com/infiniflow/ragflow)：观察文档解析、检索、服务化和产品工作流的组合。
- [GraphRAG](https://github.com/microsoft/graphrag)：验证图构建与全局/局部查询带来的收益和成本。

## 开源实践：使用、源码跟踪、最小复刻、可选贡献

- **开源使用：** 固定版本跑通 LlamaIndex 或 RAGFlow 的最小链路，并在同一数据集上运行 GraphRAG 或另一高级方案。
- **源码跟踪：** 从查询入口跟踪到检索、后处理和 Context 组装；记录关键对象、配置传播与异常路径。
- **最小复刻：** 独立实现 BM25 或简化倒排检索、向量检索和 Reciprocal Rank Fusion，并用小语料验证排名。
- **可选贡献：** 为解析器边界、评测示例、错误消息或可复现缺陷提交文档、测试或小修复。

## 项目增量

独立仓库 `production-rag-system` 至少包含版本化摄取流水线、四种检索配置、权限过滤、引用、无答案策略、离线评测、API、测试和运行说明。索引可重建，原始语料许可和来源可追踪，配置不得混入代码。

## 评测与复盘

建立“解析/切分 → 召回 → 排序 → 上下文 → 生成 → 引用”的错误分类。对质量增益与额外延迟/成本做消融，记录哪类查询从 Hybrid、Rerank 或高级方案获益，避免因平均分提高就默认使用复杂方案。

## 面试训练

- 从数据进入系统到带引用答案说明完整 RAG 数据流。
- 解释 Dense、Sparse、Hybrid 和 Rerank 的互补关系与失败模式。
- 设计带租户权限、删除传播和增量更新的企业 RAG。
- 排查“召回指标好但答案差”与“答案正确但引用错误”。
- 用对比数据说明为何采用或拒绝 GraphRAG/Agentic RAG。

## 退出证据

- `production-rag-system` 固定版本、可重建索引、API、测试和公开运行说明。
- Naive、Hybrid、Rerank 和一种高级 RAG 的完整对比报告。
- 覆盖检索、生成、引用、成本和延迟的评测数据及失败样例。
- 一条开源查询调用链和可运行的检索融合最小复刻。
- 能进行企业 RAG 系统设计、故障定位和项目取舍答辩。
