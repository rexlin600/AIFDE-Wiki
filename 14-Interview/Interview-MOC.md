# 面试准备 MOC

## 使用原则

面试准备围绕可迁移的判断与可核验项目证据组织，不积累脱离约束的标准答案。回答先澄清目标、输入、规模、风险和成功标准，再提出方案、权衡、验证与失败处理；涉及真实经历时区分个人贡献、团队结果和无法公开的信息。

## 能力分类

| 分类 | 典型考察 | 建议证据 |
| --- | --- | --- |
| 实用编码 | 数据处理、API、SQL、测试、调试与边界条件 | 可运行代码、测试和故障定位过程 |
| AI 原理 | 损失、泛化、Embedding、Attention、推理与不确定性 | 推导、最小实验和反例 |
| RAG/Agent | 摄取、检索、重排、引用、状态、工具与恢复 | 固定评测集、Trace 和错误分类 |
| 系统设计 | 容量、数据流、接口、存储、部署与演进 | 架构图、SLO、ADR 和替代方案 |
| 生产故障 | 告警、分级、遏制、恢复、沟通和复盘 | 时间线、Runbook 与预防措施 |
| 项目答辩 | 问题、约束、决策、结果、个人责任与局限 | Repository、固定版本、指标和复盘 |
| 客户场景 | Discovery、范围、价值、安全、采用和交接 | 访谈摘要、验收标准与决策日志 |
| 行为面试 | 冲突、失败、领导、反馈、模糊性与诚信 | STAR 结构和可验证结果 |

## 回答质量门槛

- 术语有定义，结论有适用条件。
- 指标说明数据集、口径、基线与误差，不报孤立数字。
- 至少给出一个失败模式、监控信号和恢复办法。
- 能说明为什么不选替代方案，以及什么证据会改变决策。
- 项目证据指向公开档案；没有证据时明确说是设计题或模拟题。
