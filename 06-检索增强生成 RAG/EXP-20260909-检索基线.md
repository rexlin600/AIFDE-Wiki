# 检索基线实验设计

> 本页是尚未执行的实验协议，不是结果报告。外部实验仓库、不可变 Commit 和最终数据集尚未建立，因此对应字段保持为空，所有结果单元格明确标记为未运行。

## 假设

在同时包含精确词项查询与语义改写查询的公开评测集上，[混合检索](./%E6%B7%B7%E5%90%88%E6%A3%80%E7%B4%A2%20Hybrid%20Search.md)相对于单独 BM25 或 Dense Retrieval 能提高至少一个预先声明的检索质量指标；该改善不应以突破预先批准的 p95 延迟和单查询成本护栏为代价。

这是可证伪假设：若 Hybrid 在总体和预定义查询切片上均未改善 Recall@k、MRR 或 nDCG@k，或者改善伴随不可接受的延迟/成本，则不支持采用 Hybrid。具体阈值必须在运行前根据目标环境填写到实验配置，不能在看到结果后调整。

## 环境

执行前由外部实验仓库的锁定配置记录以下信息：

- CPU/GPU 型号与数量、内存、操作系统和区域。
- Python、检索库、向量索引库与依赖锁文件版本。
- BM25 参数、Embedding 模型的官方标识与修订版本、向量相似度和索引参数。
- 冷/热缓存策略、并发数、预热次数、计时边界和成本单价来源日期。

当前尚无真实运行环境，因而本页不填设备、模型版本或性能数字。

## 数据集

最终数据集必须是可公开获取的检索数据集，并在运行前按以下标准确定：

1. 包含语料、查询和查询—文档相关性判断（qrels），能计算排名指标。
2. 许可允许下载、派生索引和发布汇总指标；记录版本、下载地址与校验和。
3. 至少能形成“精确词项/实体/编号”和“释义/同义表达”两个事先定义的查询切片。
4. 规模能在可用硬件上为三组方案建立同一语料版本的索引。
5. 不含需要上传的私有、客户或个人敏感数据。

[BEIR](https://github.com/beir-cellar/beir) 的公开任务可作为候选，因为其论文与官方仓库提供异构语料、查询和 qrels；选择具体任务前仍需核验该任务自身的许可、版本和下载完整性。选定后才填写 Front Matter 的 `dataset`，本设计不把候选写成已使用数据。

## 变量

### 自变量

| 组别 | 候选生成 | 融合 | Rerank |
| --- | --- | --- | --- |
| A：BM25 | 固定 BM25 Top-N | 无 | 无 |
| B：Dense | 固定编码器与向量索引 Top-N | 无 | 无 |
| C：Hybrid | 与 A、B 相同的各 Top-N | 预注册的 RRF | 无 |

Rerank 不进入首轮三组基线，避免把召回与精排收益混在一起；若后续加入，应作为独立因子建立新组，并保持输入候选集可追踪。

### 因变量

- 质量：Recall@k、MRR、nDCG@k，`k` 在运行前固定。
- 性能：端到端检索 p50/p95 延迟和吞吐；索引构建时间单独报告。
- 成本：Embedding 建索引一次性成本、索引存储、每查询计算或 API 成本。

### 控制变量与混杂因素

三组使用相同语料内容、切分、qrels、查询顺序、过滤规则、硬件、并发和测量轮次。固定随机种子并记录近似近邻索引参数。缓存状态、Embedding 批大小、网络抖动、库实现差异和查询切片分布可能造成混杂，必须逐项记录。

## 步骤

1. 选定数据集并记录许可、版本、原始文件校验和和固定 train/dev/test 划分；测试集只用于最终报告。
2. 生成规范化后的语料与查询清单，保存转换脚本、配置和输出校验和。
3. 用相同文档单元分别构建 BM25 与 Dense 索引，记录构建耗时、大小和模型修订版本。
4. 在开发集上预注册 `k`、各分支 Top-N、RRF 常数、延迟/成本护栏和查询切片；冻结配置。
5. 对每组执行一次预热和多次测量，原样保存逐查询排名、耗时、错误与成本输入。
6. 用同一评测器计算总体与切片指标；保留均值之外的分位数、失败样例和运行元数据。
7. 仅在运行完成后填写结果、结论、仓库 URL 和不可变 Commit，并由另一人按 Commit 复现。

## 指标

- **Recall@k**：至少一个相关文档是否出现在前 `k` 个结果；若每个查询有多个相关文档，还应同时报告召回到的相关文档比例并明确口径。
- **MRR**：第一个相关文档名次倒数的查询平均值，适合关注首个可用证据的位置。
- **nDCG@k**：按分级相关性累计折损收益，并用理想排序归一化；只有二元 qrels 时必须说明。
- **延迟**：从检索请求进入到返回排序文档 ID 的单调时钟耗时，报告 p50、p95、样本量、缓存状态和并发。
- **成本**：将建索引与查询成本分开。查询成本按实际计算时长或供应商账单单位计算，并附单价、币种和日期；无账单证据时不估造金额。

主指标和护栏由实验配置在运行前声明。除点估计外，使用按查询重采样的置信区间或配对检验，并报告多次运行波动；具体统计方法也应预注册。

## 有效性威胁

- 公开数据集与目标企业语料在语言、长度、时效和查询意图上可能不同，结果不能直接外推。
- qrels 往往不完整；未标注文档可能实际相关，尤其会影响新检索器的评估。
- 在开发集调参过多会高估泛化效果，因此测试集必须保持封存。
- 单机热缓存结果不能代表多租户、冷启动或网络服务的线上长尾延迟。
- 不同实现的优化程度可能被误认为算法差异，应公开配置与逐查询输出供审查。

## 复现信息

外部仓库建立后应实现以下稳定命令接口；这是一份接口约定，当前 Wiki 仓库中没有对应可执行模块：

```bash
python -m retrieval_baseline.prepare --config configs/baseline.yaml
python -m retrieval_baseline.index --config configs/baseline.yaml --retriever bm25
python -m retrieval_baseline.index --config configs/baseline.yaml --retriever dense
python -m retrieval_baseline.run --config configs/baseline.yaml --retriever bm25
python -m retrieval_baseline.run --config configs/baseline.yaml --retriever dense
python -m retrieval_baseline.run --config configs/baseline.yaml --retriever hybrid-rrf
python -m retrieval_baseline.evaluate --config configs/baseline.yaml
```

每条命令必须把解析后的配置、数据校验和、随机种子、模型修订、依赖锁摘要和逐查询输出写入同一运行目录。完成首个真实运行后，在 Front Matter 填写真实 `repository`、完整 `commit` 和 `dataset`，并将 `maturity` 从 `draft` 改为 `reviewed`；不得使用示例域名或伪造哈希。
