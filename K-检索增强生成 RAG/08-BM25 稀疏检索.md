# BM25 稀疏检索

<!-- markdownlint-disable MD012 MD013 -->

## 它解决什么 RAG 问题

BM25 依靠查询与文档共享词项检索，特别适合错误码、产品名、法规编号和专有术语。相比“出现次数越多越相关”的简单关键词计数，它降低常见词影响，让词频收益饱和，并校正文档长度。

## 不理解会造成什么错误

- 认为一个词出现 20 次就比出现 2 次相关十倍。
- 中文未正确分词，查询词和文档词根本无法匹配。
- IDF 公式或平滑方式不同，却直接比较跨系统分数。
- 用 BM25 分数当概率，或与余弦分数直接相加。

## 它在 RAG 链路中的位置

`规范化与分词 → 倒排索引 → 查询词查 Posting → BM25 打分 → Sparse Top-N`。倒排表保存每个词出现在哪些文档及词频，查询无需扫描全部正文。

## 从错误码检索开始

查询 `E1047 连接失败`。简单基线按共享词个数排序；它让常见词和罕见错误码权重相同。BM25 用 IDF 提高罕见词价值，同时防止堆砌“失败”一词刷高分数。

## 逐步推导 BM25

语料有 $N$ 篇文档，词 $t$ 出现在 $df(t)$ 篇中。常用平滑 IDF 为：

$$
\operatorname{IDF}(t)=\ln\left(1+\frac{N-df(t)+0.5}{df(t)+0.5}\right)
$$

设 $f(t,d)$ 是词频，$|d|$ 是文档长度，$avgdl$ 是平均长度。长度归一项为：

$$
K_d=k_1\left(1-b+b\frac{|d|}{avgdl}\right)
$$

单词贡献为：

$$
\operatorname{score}(t,d)=\operatorname{IDF}(t)
\frac{f(t,d)(k_1+1)}{f(t,d)+K_d}
$$

当词频趋向无穷，分数趋近 $\operatorname{IDF}(t)(k_1+1)$，所以收益会饱和。$b=0$ 不校正文档长度，$b=1$ 完全按相对长度校正。查询总分是查询词贡献之和。

## 最小手算

设 $N=3$，词“E1047”仅出现在 1 篇，IDF 为 $\ln(1+2.5/1.5)\approx0.981$。取 $k_1=1.2,b=0.75$，某文档长度等于平均长度且词频为 2，则 $K_d=1.2$：

$$
0.981\times\frac{2\times2.2}{2+1.2}\approx1.349
$$

若词频从 2 增到 20，贡献约 2.036，并不会增大十倍。

## 可执行实验

```python
import math
from collections import Counter

docs = ["E1047 连接 失败", "连接 失败 失败 失败 服务", "密码 重置"]
tokenized = [doc.split() for doc in docs]
avgdl = sum(map(len, tokenized)) / len(tokenized)

def idf(term):
    df = sum(term in doc for doc in tokenized)
    return math.log(1 + (len(tokenized) - df + 0.5) / (df + 0.5))

def bm25(query, doc, k1=1.2, b=0.75):
    counts = Counter(doc)
    norm = k1 * (1 - b + b * len(doc) / avgdl)
    return sum(idf(term) * counts[term] * (k1 + 1) / (counts[term] + norm)
               for term in query if counts[term])

query = ["E1047", "失败"]
scores = [bm25(query, doc) for doc in tokenized]
ranking = sorted(range(len(docs)), key=lambda i: -scores[i])
print(scores, ranking)
assert ranking[0] == 0  # 罕见错误码胜过重复常见词
assert idf("E1047") > idf("失败")
assert bm25(["不存在"], tokenized[0]) == 0
```

## 实验结果边界

实验验证罕见词权重、词频饱和后的排序与零匹配分支。三篇模拟文本不能代表真实质量；分词、同义词、字段权重、参数和平滑变体必须在固定 qrels 上评测。

## 质量延迟与成本影响

BM25 索引通常稀疏且 CPU 查询高效，适合精确词。索引保存词典和 Posting，占用随不同词数与出现次数增长。`k1`、`b`、分词器、停用词和 Top-N 都要版本化；扩大候选会增加重排序成本。

## 数据评测与安全风险

权限过滤必须在 Posting 候选读取边界生效。日志中的查询可能含账号和错误详情，应脱敏。评测按编号、专名、自然语言和零结果切片；同一文档近重复版本不要跨训练与测试。

## 工程排错

| 现象 | 可能原因 | 优先检查 |
| --- | --- | --- |
| 精确编号搜不到 | 分词或大小写规范化错误 | Analyzer、Token、倒排表 |
| 长文档总排前 | 长度归一未生效 | 文档长度、avgdl、b 参数 |
| 常见词主导 | IDF 或停用词配置错误 | df、IDF 公式、词典 |
| 分数跨索引突变 | 语料统计或分词器变化 | 索引版本、N、df、Analyzer |
| 授权结果不足 | 过滤太晚或 Top-N 太小 | ACL 下推、过滤后 Recall |

## 适用与不适用场景

适合共享词明确、错误码和专名重要的任务。只有同义改写且几乎无词面重合时，Dense 可能更好；通常先用 BM25 建立廉价可解释基线，再由错误分析决定是否混合。

## 学习收益

你应能从 df、词频和长度手算 BM25，解释饱和与归一化，并追踪分词到倒排候选的数据流。

## 给别人讲清楚

“BM25 会奖励稀有且匹配的词，但同一个词重复很多次的收益会逐渐变小；它还避免长文档只因词多就天然占优。”
