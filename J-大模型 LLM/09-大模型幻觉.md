# 大模型幻觉

<!-- markdownlint-disable MD012 MD013 -->

## 它解决什么 LLM 问题

大模型幻觉是输出流畅、形式合理，却缺少输入或可靠来源支持的内容。客服可能编造退款政策，知识助手可能伪造引用，工具助手可能声称操作成功。理解幻觉的意义不是追求一个“绝不出错”的开关，而是把错误拆成可检测、可拒答、可评测的类别。

## 不理解会造成什么错误

- 把任何答错都归因于模型参数，忽略检索、上下文和工具故障。
- 要求模型“不要幻觉”，却不给证据或拒答出口。
- 只评流畅度，不核对每个事实主张是否有支持。
- 引用存在就判定正确，不检查引用是否真的支持结论。
- 为提高回答率而取消拒答，使高风险错误增加。

## 它在 LLM 链路中的位置

幻觉是生成结果与可用证据之间的故障表现。先判断问题是否可回答，再检查检索或工具是否提供证据，最后核验答案中的主张。Prompt 能说明规则，RAG 和工具能提供外部事实，结构化输出能约束格式，但都不能单独保证事实正确。

## 先区分五类错误

- 事实幻觉：日期、数值或实体关系错误。
- 归因幻觉：内容可能正确，但引用并不支持它。
- 无证据扩写：输入只说明 A，回答自行补出 B。
- 工具结果幻觉：没有执行工具却声称已查询或已提交。
- 指令冲突：不可信文档诱导模型违背系统规则。

分类决定处理方法。知识缺失先考虑检索；证据不足应拒答；工具状态只能由执行器确认；权限不能交给语言模型判断。

## 可回答性先于正确性

设问题真实是否可由当前证据回答为 $A\in\{0,1\}$，系统选择回答或拒答。四种结果是：可回答且回答正确、可回答却错误拒答、不可回答而正确拒答、不可回答却强答。高风险任务应对“不可回答却强答”设置更高代价。

若回答阈值为 $\tau$，只有证据支持度 $s\ge\tau$ 才回答。提高 $\tau$ 往往降低覆盖率并提高已回答样本的可靠性，因此必须同时报告：

$$
\text{覆盖率}=\frac{\text{已回答数}}{\text{总问题数}},\qquad
\text{选择性准确率}=\frac{\text{回答正确数}}{\text{已回答数}}
$$

## 主张级支持率

把答案拆为可核验主张 $c_1,\ldots,c_m$。若 $z_i=1$ 表示证据直接支持主张 $i$，则：

$$
\text{支持率}=\frac{\sum_i z_i}{m}
$$

重要主张可加权。引用质量还需分别检查“引用存在”“引用可访问”“引用内容蕴含主张”，不能只数链接。

## 最小手算

10 个问题中系统回答 6 个，其中 5 个正确；4 个拒答中有 3 个确实不可回答。覆盖率为 $6/10=60\%$，选择性准确率为 $5/6\approx83.3\%$，正确拒答率为 $3/4=75\%$。只说“准确率 80%”会隐藏系统到底是靠拒答还是靠正确回答。

## 可执行实验

```python
cases = [
    # support score, answerable, answer would be correct
    (0.95, True, True),
    (0.80, True, True),
    (0.65, True, False),
    (0.45, True, True),
    (0.30, False, False),
    (0.10, False, False),
]

def evaluate(threshold):
    answered = [(a, correct) for score, a, correct in cases if score >= threshold]
    correct_answers = sum(a and correct for a, correct in answered)
    false_answers = sum(not a or not correct for a, correct in answered)
    coverage = len(answered) / len(cases)
    precision = correct_answers / len(answered) if answered else 1.0
    return coverage, precision, false_answers

loose = evaluate(0.40)
strict = evaluate(0.70)
print("loose", loose, "strict", strict)
assert strict[0] < loose[0]
assert strict[1] > loose[1]
assert strict[2] < loose[2]
```

实验展示阈值的覆盖率与可靠性权衡。支持分数是人为构造的，真实系统必须用独立标注校准，不能把模型自报置信度直接当概率。

## 怎样建立可靠链路

1. 将问题、证据、回答和工具状态分别记录。
2. 检索前先做权限过滤，检索后保留来源标识。
3. Prompt 要求只据证据回答，并允许明确说“不知道”。
4. 对答案做主张拆分、引用蕴含和数值一致性检查。
5. 高风险动作仍由规则、人工或确定性系统审批。
6. 把失败样本加入固定回归集，而不是只修改单个 Prompt。

## 实验结果怎样解释

降低强答错误可能增加错误拒答，不能只优化一个指标。按问题可回答性、知识时效、语言、领域、证据位置和风险等级切片。模型升级、Prompt、检索索引、工具和采样参数任一变化，都应重新跑相同评测。

## 质量延迟与成本影响

检索、重排、事实核验和二次模型审查会增加延迟与 Token 成本，但可降低无依据输出。对低风险创意任务，可减少核验；对医疗、法律、金融或执行动作，应提高阈值、缩小权限并保留人工确认。

## 数据评测与安全风险

评测题必须有明确可接受答案、来源和时间戳，并包含不可回答问题。不要把公开基准答案放入上下文或训练集。外部证据本身可能过期、恶意或无权限；“有来源”不是“来源可信”。日志中的用户问题与证据可能含敏感信息，应脱敏和限权。

## 工程排错

| 现象 | 可能原因 | 优先检查 |
| --- | --- | --- |
| 答案流畅但无引用 | 没有证据约束或拒答出口 | 上下文、主张级支持、模板 |
| 引用存在但不支持 | 只检查链接存在 | 引用片段与主张蕴含 |
| 新事实经常答错 | 参数知识过期 | RAG、工具、来源日期 |
| 明明有证据却拒答 | 阈值过高或证据排序差 | 覆盖率、召回、位置切片 |
| 声称工具已执行 | 模型文本冒充状态 | 执行日志、状态机、结果 ID |
| 更新后错误率突增 | 模型或链路版本漂移 | 固定集、版本、采样配置 |

## 适用与不适用场景

事实问答、企业知识、引用生成和工具结果解释都要治理幻觉。创意写作中的虚构不是幻觉故障，只要用户明确要求虚构；但虚构内容若冒充事实，仍需标示。没有单一指标能覆盖所有风险。

## 学习收益

你应能区分错误类型，先判断可回答性，计算覆盖率和选择性准确率，建立主张级引用核验，并解释拒答阈值的权衡。

## 给别人讲清楚

“模型的任务是生成可能的下一个 Token，不是自动查证事实。可靠系统要给它证据、允许拒答，再由程序检查答案中的每个关键主张是否真被证据支持。”

## 自检问题

1. 为什么引用存在不能证明答案有依据？
2. 提高拒答阈值会怎样影响覆盖率？
3. 工具执行成功为什么不能由模型自己宣布？
