# 大模型蒸馏

<!-- markdownlint-disable MD012 MD013 -->

## 它解决什么 LLM 问题

大模型蒸馏让较小的学生模型学习较强教师模型的输出分布、回答或中间表示，从而降低推理成本。例如，用教师生成领域问答，再训练小模型稳定完成分类、抽取或常见客服任务。

蒸馏复制的是教师在所选数据上的行为，不会自动获得教师全部能力，也会继承其事实错误、偏见和风格。

## 不理解会造成什么错误

- 把教师生成内容当成绝对正确标签。
- 只用容易提示，学生没有学到边界和拒答。
- 用测试集提示向教师生成训练答案，造成评测污染。
- 教师和学生 Tokenizer 不同，却硬对齐每个 Token 的 Logits。
- 只看压缩比，不比较端到端质量、延迟和生成长度。

## 它在 LLM 链路中的位置

先选定教师、目标任务和独立评测，再构造无污染输入，让教师产生软分布、回答或推理轨迹，经过校验后训练学生。学生可继续 SFT、偏好对齐、量化和部署。蒸馏是能力迁移，不是检索更新机制。

## 软标签比硬标签多了什么

普通监督只告诉学生正确类别。教师 Logits $z_i$ 经温度 $T$ 变成软概率：

$$
p_i^{(T)}=\frac{\exp(z_i/T)}{\sum_j\exp(z_j/T)}
$$

$T>1$ 会让分布更平滑，暴露次优类别之间的关系。学生最小化教师分布与学生分布的交叉熵或 KL 散度：

$$
L_{soft}=T^2D_{KL}(p_{teacher}^{(T)}\Vert p_{student}^{(T)})
$$

再与真实硬标签损失组合：

$$
L=\alpha L_{hard}+(1-\alpha)L_{soft}
$$

## 为什么乘以温度平方

Softmax 使用 $z/T$ 后，对 Logit 的梯度大致多一个 $1/T$；教师与学生的软概率差在高温近似下又缩小约 $1/T$，梯度量级因此约缩小为 $1/T^2$。乘 $T^2$ 用来保持软损失梯度与温度变化下大致可比。这是尺度补偿，不保证任何 $T$ 都最优。

## 最小手算

教师二分类 Logits 为 `[2,0]`。$T=1$ 时概率约 `[0.881,0.119]`；$T=2$ 时先除以 2，得到 `[1,0]`，概率约 `[0.731,0.269]`。高温让学生看到教师认为第二类仍有一定可能，而不是只有硬标签 `[1,0]`。

## 可执行实验

```python
import numpy as np

def softmax(logits, temperature):
    scaled = np.asarray(logits, dtype=float) / temperature
    scaled -= scaled.max()
    probability = np.exp(scaled)
    return probability / probability.sum()

def kl_divergence(teacher, student):
    return np.sum(teacher * np.log(teacher / student))

teacher_logits = np.array([2.0, 0.0])
student_logits = np.array([1.0, 0.5])
for temperature in (1.0, 2.0, 4.0):
    teacher = softmax(teacher_logits, temperature)
    student = softmax(student_logits, temperature)
    scaled_loss = temperature ** 2 * kl_divergence(teacher, student)
    print("T", temperature, "teacher", np.round(teacher, 3),
          "T^2 KL", round(scaled_loss, 4))

assert softmax(teacher_logits, 2.0)[1] > softmax(teacher_logits, 1.0)[1]
assert np.isclose(softmax(teacher_logits, 4.0).sum(), 1.0)
assert kl_divergence(softmax(teacher_logits, 1),
                     softmax(teacher_logits, 1)) < 1e-12
```

实验验证温度平滑与 KL 基本性质。$T^2KL$ 不会完全恒定，因为“近似抵消”只描述高温附近的梯度尺度，而不是损失数值恒等。

## 三种常见蒸馏

- Logits 蒸馏要求能访问教师概率，并处理词表与 Token 对齐。
- 响应蒸馏只保存教师文本，可用于闭源教师，但学生学到的是采样后的有限答案。
- 特征蒸馏对齐隐藏层或 Attention，需要可访问内部表示，并解决层数、宽度不同的问题。

对 LLM，响应蒸馏最容易落地。可让教师产生答案、结构化字段或解释，但应保存原始提示、教师版本、采样参数、校验结果和使用许可。

## 数据怎样构造

输入应覆盖常见、困难、不可回答、对抗和边界情况。教师输出先经规则、工具或人工核验；低置信度样本可丢弃或降权。加入真实人工标签避免学生完全复制教师偏差。严格隔离测试集及其近重复，不能让教师替测试题生成训练答案。

## 实验结果怎样解释

比较学生原始基线、硬标签训练、蒸馏训练和教师。报告任务质量、事实支持、拒答、长度、TTFT、吞吐、显存和总生成成本。学生在窄任务接近教师，不代表通用能力等价；教师与学生差距越大，迁移越可能受容量限制。

## 质量延迟与成本影响

蒸馏有一次性教师生成与学生训练成本，换取长期推理节省。教师若生成冗长答案，会提高数据和训练成本，并诱导学生变长。小模型吞吐通常更高，但端到端收益仍受 Tokenizer、量化、批处理和任务长度影响。

## 数据评测与安全风险

确认教师服务条款是否允许生成训练数据及其用途。教师可能输出个人信息、受版权约束内容或危险步骤，需过滤与审计。学生的安全能力不会自动随主任务迁移，必须重新做红队、越权、拒答和多语言评测。

## 工程排错

| 现象 | 可能原因 | 优先检查 |
| --- | --- | --- |
| 学生只会模板答案 | 输入覆盖过窄 | 意图、长度、困难样本切片 |
| 蒸馏后事实错误增多 | 教师答案未核验 | 来源、工具校验、人工抽样 |
| Logits 无法对齐 | Tokenizer 或词表不同 | Token 映射、改用响应蒸馏 |
| 高温训练不稳定 | 温度、缩放或权重错误 | $T^2$、alpha、梯度范数 |
| 测试分数异常高 | 测试提示泄漏 | 指纹、近重复、生成日志 |
| 小模型没有成本优势 | 输出更长或服务未优化 | Token 数、批量、量化、吞吐 |

## 适用与不适用场景

适用于任务分布稳定、调用量大、教师明显更强且可合法使用其输出的场景。不适用于事实频繁变化、必须覆盖教师全部通用能力或缺乏可靠评测的场景。动态事实优先 RAG，少量行为示范可先做 SFT。

## 学习收益

你应能解释软标签和温度，推导 $T^2$ 的尺度作用，区分 Logits、响应与特征蒸馏，并设计防止教师错误和测试污染的数据流程。

## 给别人讲清楚

“蒸馏像让小模型跟强教师做大量练习。软标签不只给标准答案，还透露其他答案有多像；但老师讲错的内容，学生也可能学错，所以必须核验和考试。”
