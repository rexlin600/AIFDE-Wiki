# 大模型量化

<!-- markdownlint-disable MD012 MD013 -->

## 它解决什么 LLM 问题

大模型权重和 KV Cache 会占用大量显存。量化用更少的比特表示数值，使同一设备能装下更大的模型，并可能降低内存带宽和推理成本。例如，70 亿个参数若只计算权重本体，FP16 约需 14 GB，INT8 约需 7 GB，INT4 约需 3.5 GB。

量化是“近似表示”，不是无损压缩。真正的问题是：在任务质量可以接受的前提下，能节省多少内存、是否真的加速，以及运行硬件是否支持相应低精度内核。

## 不理解会造成什么错误

- 看到 4 bit 就断言端到端速度一定提升。
- 只测平均困惑度，不测代码、数学、长文本等敏感任务。
- 把权重位宽当成进程总显存，遗漏激活、KV Cache 和运行时工作区。
- 用少量、失真的校准数据确定量化范围。
- 混淆训练量化、权重量化与 KV Cache 量化。

## 它在 LLM 链路中的位置

预训练或微调得到浮点权重后，可以进行训练后量化并部署；量化感知训练则在训练时模拟舍入误差。请求进入服务后，低比特权重参与矩阵乘法，输出仍可在较高精度累加。它与 KV Cache、批处理和服务引擎共同决定显存与吞吐。

## 从舍入开始理解

浮点数能表达很细的间隔，低比特整数只有有限刻度。对称量化先选择缩放因子 $s$，再把 $x$ 映射到整数 $q$：

$$
q_{\max}=2^{b-1}-1,\qquad
s=\frac{\max_i|x_i|}{q_{\max}}
$$

$$
q_i=\operatorname{clip}\left(\operatorname{round}\left(\frac{x_i}{s}\right),-q_{\max},q_{\max}\right),
\qquad \hat{x}_i=sq_i
$$

$b$ 是位宽，$\hat{x}$ 是反量化近似值。误差 $e_i=x_i-\hat{x}_i$ 来自舍入和截断。若数值没有被截断，最近邻舍入通常满足 $|e_i|\le s/2$。

## 最小手算

把 $[-1, -0.3, 0.2, 1]$ 对称量化为有符号 3 bit。此时 $q_{\max}=3$，$s=1/3$。整数约为 $[-3,-1,1,3]$，反量化为 $[-1,-0.333,0.333,1]$。其中 0.2 的误差约为 0.133。

离群值会把 $s$ 拉大，使多数小数值共用过粗的刻度。按输出通道分别选择 scale 通常比整个矩阵共用一个 scale 更准确，但元数据和内核更复杂。

## 可执行实验

```python
import numpy as np

def symmetric_quantize(values, bits):
    qmax = 2 ** (bits - 1) - 1
    scale = np.max(np.abs(values)) / qmax
    integers = np.clip(np.rint(values / scale), -qmax, qmax).astype(int)
    restored = integers * scale
    return integers, restored, scale

weights = np.array([-1.0, -0.3, 0.2, 1.0])
for bits in (3, 8):
    integers, restored, scale = symmetric_quantize(weights, bits)
    error = np.mean((weights - restored) ** 2)
    print(bits, "bit", "scale", round(scale, 5),
          "q", integers, "mse", round(error, 7))

_, restored3, scale3 = symmetric_quantize(weights, 3)
_, restored8, _ = symmetric_quantize(weights, 8)
assert np.all(np.abs(weights - restored3) <= scale3 / 2 + 1e-12)
assert np.mean((weights - restored8) ** 2) < np.mean((weights - restored3) ** 2)

parameters = 7_000_000_000
for bits in (16, 8, 4):
    gib = parameters * bits / 8 / 1024 ** 3
    print(bits, "bit weight only GiB", round(gib, 2))
```

实验说明位宽越高，刻度通常越细，但这不是“任何情况下误差都严格单调”的理论保证；真实方案还可能分组、保留异常通道或使用非对称码本。

## 方案怎样选择

- 权重仅量化适合先降低模型装载成本，激活仍用 FP16 或 BF16。
- 权重与激活量化能进一步减少带宽，但对异常值和内核要求更高。
- KV Cache 量化主要解决长上下文和高并发的缓存成本，要单独评估长序列质量。
- 训练后量化部署快；量化感知训练成本更高，但可让模型适应误差。
- Per-channel 或 group-wise 量化精度通常更好，代价是 scale 更多、实现更复杂。

## 实验结果怎样解释

小矩阵的均方误差只能证明数值近似。生产验收至少要比较固定任务集上的准确率、生成稳定性、长上下文、吞吐、首 Token 延迟、显存峰值和能耗。应与同一模型的浮点版本比较，并固定提示模板、采样参数和服务负载。

## 质量延迟与成本影响

权重内存的理想值约为 $N b/8$ 字节，但实际还有 scale、零点、分组元数据、未量化层、激活和缓存。低比特权重减少数据搬运，只有硬件与内核高效支持时才会转化为速度；反量化开销或小批量可能抵消收益。

## 数据评测与安全风险

校准集应覆盖语言、代码、数值范围、上下文长度和真实提示格式，且不能混入测试答案。量化可能让拒答边界、JSON 格式和小概率安全行为发生变化，因此不能只复用浮点模型的安全结论。发布时记录模型版本、量化算法、位宽、分组大小、校准集版本和运行硬件。

## 工程排错

| 现象 | 可能原因 | 优先检查 |
| --- | --- | --- |
| 显存没有按位宽下降 | KV、激活或部分层仍为浮点 | 分项显存、权重格式、加载日志 |
| 低比特反而更慢 | 缺少优化内核或批量过小 | 硬件支持、算子追踪、批大小 |
| 数学和代码能力骤降 | 异常通道被粗糙量化 | 分通道误差、敏感层、校准样本 |
| 长文本后质量下降 | KV Cache 精度不足 | 缓存 dtype、长度切片评测 |
| 同一模型结果不一致 | 后端或量化配置不同 | 算法、group size、版本与随机种子 |

## 适用与不适用场景

量化适合受显存、内存带宽或部署成本限制的推理。若模型已很小、延迟主要来自排队和网络，量化未必解决瓶颈。对极敏感的数值任务，应先保留关键层高精度或继续使用浮点模型。

## 学习收益

你应能从位宽估算权重内存，推导对称量化和误差范围，区分权重、激活、KV Cache 量化，并设计浮点对照实验。

## 给别人讲清楚

“量化像把连续刻度换成更少的格子：模型更省空间，但数值会被四舍五入。省下的显存不自动等于更快，必须在目标硬件上同时测质量和速度。”
