# 大模型生成采样

<!-- markdownlint-disable MD012 MD013 -->

## 它解决什么 LLM 问题

模型每一步输出的是整个词表的 Logits，而不是唯一答案。生成采样规定怎样把这个分布变成一个 Token，并在何时停止。温度、top-k 和 top-p 改变候选集合与随机程度，因此直接影响重复、创造性、可复现性、长度、延迟和成本。

采样不会给模型增加新知识，也不能修复提示泄漏、事实错误或权限问题。它只决定如何从模型已有的条件分布中选择路径。

## 不理解会造成什么错误

- 把温度设为 0 后仍套除法，产生除零或 NaN；确定性生成应单独用 Greedy。
- 先抽样再做 top-k/top-p，过滤已经失去作用。
- 把随机种子当成跨模型、硬件和版本都可复现的保证。
- 只依赖 EOS，模型不输出时无限生成并持续计费。
- 通过降低温度掩盖幻觉，以为更稳定的错误就是更真实。

## 它在 LLM 链路中的位置

```text
最后位置 Logits [B,V]
→ 可选约束与惩罚
→ 温度缩放
→ top-k 或 top-p 过滤
→ Softmax 概率 [B,V]
→ 选择 Token [B]
→ 停止判断 → 追加并继续 Decode
```

上游是[大模型自回归 Transformer](<04-大模型自回归 Transformer.md>)，下游会把新 Token 放入下一步输入或[大模型 KV Cache](<14-大模型 KV Cache.md>)。

## 从客服回复生成开始

客服机器人需要生成清晰但受控的回复：

- 事实字段必须来自订单工具，不允许采样改写金额；
- 普通解释可保留少量措辞变化；
- 遇到 EOS、结构化结束符或最大 Token 数必须停止；
- 线上记录模型版本、采样参数和响应长度，支持问题复现。

高风险字段适合结构化约束或模板，不能只把温度调低。

## 先建立简单基线

Greedy 每步选择最大 Logit：

$$
x_{t+1}=\arg\max_i z_i
$$

它容易复现、速度简单，是抽取、分类式回答和回归测试的首选基线。但每一步局部最优不保证整段序列概率最高，也容易进入重复或单调路径。

## 从 Logits 到概率

对词表 Logits $z_i$，温度 $\tau>0$ 后的概率是：

$$
p_i(\tau)=
\frac{\exp(z_i/\tau)}{\sum_j\exp(z_j/\tau)}
$$

计算时先减最大 Logit，避免指数溢出：

$$
p_i=\frac{\exp((z_i-z_{max})/\tau)}
{\sum_j\exp((z_j-z_{max})/\tau)}
$$

### 温度为什么改变尖锐程度

两个 Token 的概率比为：

$$
\frac{p_i}{p_j}=\exp\left(\frac{z_i-z_j}{\tau}\right)
$$

当 $\tau<1$，Logit 差异被放大，分布更集中；当 $\tau>1$，差异被压缩，分布更平。$\tau\to0^+$ 时趋近 Greedy，但工程上应直接走 `argmax` 分支。

## top-k 怎样限制候选数

top-k 只保留 Logit 最大的 $k$ 个 Token，其余设为 $-\infty$，然后重新 Softmax。它提供固定候选数，但不同上下文的概率尾部可能差异很大：有时第 10 名仍合理，有时第 3 名已经极不可信。

## top-p 怎样适应分布形状

将概率从大到小记为 $p_{(1)}\ge p_{(2)}\ge\cdots$，选择最小集合 $S$，使：

$$
\sum_{i\in S}p_i\ge p_{threshold}
$$

只在 $S$ 内重新归一化采样。分布尖锐时集合小，分布平坦时集合大。top-p 是概率质量阈值，不能误写成“保留每个概率大于 p 的 Token”。

## 最小手算

Logits 为 `[2,1,0]`，温度 1 时先减 2，指数约为
`[1,0.368,0.135]`，归一化概率约 `[0.665,0.245,0.090]`。

- top-k=2 保留前两项，重新归一化约 `[0.731,0.269,0]`；
- top-p=0.8 时，第一项累计 0.665 不足，加入第二项后 0.910 达标，所以候选仍是前两项；
- 温度 0.5 时概率比 $p_1/p_2=e^{(2-1)/0.5}=e^2$，比温度 1 的 $e$ 更大。

## 可执行采样实验

```python
import numpy as np

rng = np.random.default_rng(42)

def probabilities(logits, temperature=1.0, top_k=None, top_p=None):
    if temperature <= 0:
        raise ValueError("temperature must be positive; use greedy for zero")
    scores = np.asarray(logits, dtype=float) / temperature
    if top_k is not None:
        if not 1 <= top_k <= scores.size:
            raise ValueError("top_k is outside the vocabulary")
        keep = np.argpartition(scores, -top_k)[-top_k:]
        scores = np.where(np.isin(np.arange(scores.size), keep), scores, -np.inf)
    scores -= np.max(scores)
    probs = np.exp(scores)
    probs /= probs.sum()
    if top_p is not None:
        if not 0 < top_p <= 1:
            raise ValueError("top_p must be in (0, 1]")
        order = np.argsort(probs)[::-1]
        cumulative = np.cumsum(probs[order])
        count = np.searchsorted(cumulative, top_p, side="left") + 1
        keep = order[:count]
        probs = np.where(np.isin(np.arange(probs.size), keep), probs, 0.0)
        probs /= probs.sum()
    return probs

base = probabilities([2.0, 1.0, 0.0])
cold = probabilities([2.0, 1.0, 0.0], temperature=0.5)
nucleus = probabilities([2.0, 1.0, 0.0], top_p=0.8)
assert np.allclose(base.sum(), 1.0)
assert cold[0] > base[0]
assert np.count_nonzero(nucleus) == 2

# 用转移 Logits 模拟离线逐 Token 生成；ID 3 是 EOS。
transition = np.array([
    [0.0, 3.0, 1.0, -2.0],
    [0.0, 0.5, 2.0, -1.0],
    [-1.0, 0.0, 0.0, 4.0],
    [-np.inf, -np.inf, -np.inf, 0.0],
])
tokens = [0]
for _ in range(8):
    p = probabilities(transition[tokens[-1]], temperature=0.8, top_k=2)
    next_token = int(rng.choice(len(p), p=p))
    tokens.append(next_token)
    if next_token == 3:
        break
assert len(tokens) <= 9
assert tokens[-1] == 3
print("base", base.round(3), "cold", cold.round(3), "tokens", tokens)
```

固定种子让本例稳定复现。真实框架即使种子相同，也可能因设备、并行顺序、内核和模型版本不同而变化。

## 实验结果解释

实验验证温度降低后头部概率上升、top-p 保留达到阈值的最小前缀，并展示 EOS 或长度上限的双重停止。它没有证明某组参数适合所有任务。参数必须通过固定任务集、多种子与业务指标选择，而不是凭单个“看起来不错”的回答。

## 停止条件与输出约束

可靠生成至少要同时处理：

- EOS Token；
- 最大新 Token 数；
- 请求超时或用户取消；
- 结构化语法完成状态；
- 安全策略触发的终止或转交。

字符串停止序列可能跨 Token 边界，必须在 Token 与解码文本层明确实现语义。达到长度上限属于“被截断”，不能伪装成完整答案。

重复惩罚和频率惩罚会在采样前修改 Logit。它们可能减少复读，也可能破坏代码、编号或专有名词，必须按内容类型切片验证。

## 质量延迟与成本影响

- Greedy 和随机采样的模型前向成本近似相同，候选过滤通常不是主要耗时。
- 最大新 Token 数直接限制最坏完成延迟和输出费用。
- Beam Search 会维护多条候选，增加计算与内存；开放对话并不必然获益。
- 更高温度通常增加多样性，也可能增加格式失败和不稳定性。
- 批量服务中，不同请求的停止时间不同，会影响批次利用率和尾延迟。

评测应同时记录任务正确率、格式成功率、重复率、平均及 P95 输出长度、首 Token 延迟和完成延迟。

## 数据评测与安全风险

- 调采样参数必须使用验证集，不能反复查看测试集挑最好结果。
- 自动评分器可能偏爱冗长回答，需要人工审核关键失败样本。
- 低温度只让输出更稳定，不会把错误知识变成事实。
- 随机生成要覆盖多种子，尤其测试越权、仇恨、自伤和隐私场景。
- 停止词来自用户时需防注入，不能允许它绕过结构或安全检查。

## 工程排错

| 现象 | 可能原因 | 优先检查 |
| --- | --- | --- |
| 输出每次完全相同 | Greedy、温度过低或候选只剩一个 | 解码策略、过滤后非零概率数 |
| 输出杂乱且格式失败 | 温度过高或尾部候选过多 | 温度、top-p、Schema 约束 |
| top-p 后没有候选 | 累计阈值实现错误 | 排序、首个越过阈值项是否保留 |
| 生成不停止 | EOS 配置错或模型不输出 EOS | Tokenizer ID、长度和超时兜底 |
| 固定种子仍有差异 | 模型或并行内核不同 | 版本、设备、批次与确定性配置 |
| 回答稳定但事实错误 | 采样不能修复知识问题 | 来源、RAG、工具和事实评测 |

## 适用与不适用场景

Greedy 适合回归测试、窄任务和确定性优先场景；较低温度配合 top-p 常用于受控助手；更开放的创作可增加多样性，但仍要有限制和审核。金额计算、权限决定和不可逆操作不应由随机 Token 直接决定，应转为程序验证与受控工具。

## 学习收益

你应能从 Logits 稳定计算概率，推导温度对概率比的影响，区分 top-k 与 top-p，写出有种子和停止上限的生成循环，并用质量、延迟与成本共同选择参数。

## 给别人讲清楚

### 复述检查

请尝试说明：“模型给全词表打分，采样先调整分布和候选范围，再从剩余概率中选一个 Token。温度控制分布尖锐程度，top-k 限制数量，top-p 限制累计概率质量，停止条件限制生成生命周期。”

## 自检问题

1. 为什么温度为 0 时不应直接做 Logit 除法？
2. top-p=0.9 是否表示删除概率低于 0.9 的 Token？
3. 固定随机种子为什么不保证跨环境逐 Token 一致？
4. 哪些停止条件应同时存在？
5. 为什么降低温度不能解决幻觉？
